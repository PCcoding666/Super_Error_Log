# 隐私与未成年人数据说明

## 当前学生邀请码网页版（2026-10-15 起，2026-10-22 更新）

启用 `SEL_STUDENT_HOST_ENABLED=1` 时以下规则优先于历史的配对/本机角色说明：

- `/s/` 每名学生有独立数据目录和服务进程。邀请码 12 位，**60 天内可重复登录**（2026-10-21 起；更早的 7 天一次性旧码仍按一次性规则）；注册表只存邀请码与登录令牌的 SHA256。登录后用 `sel_student` Cookie（HttpOnly、Secure、SameSite=Lax、Path=/s）保持登录 30 天，**活跃使用时滑动续期**（每天最多顺延一次，连续 30 天不用才需要重新输码）。
- 登录、退出与补码由服务器管理。退出撤销当前会话，清除本机页面标记，不删除服务器学习记录。新学生空间不导入旧App的测试数据。
- 浏览器不能选择学生ID、存储目录或内部服务端口。内部设备令牌只在服务器进程间传递，不发给浏览器。新入口禁止旧 `/s/pair` 配对方式绕过邀请码。
- 注册上限缺省 100 个学生空间（`SEL_MAX_STUDENTS`），每人仍是独立目录和独立进程。
- 语音与图片仍经服务器发送百炼处理，具体范围见下文；“本应用不保存录音”不代表对第三方留存政策作保证。
- 学生发现识别错误时可主动修改；不要求每题校对。历史章节中的强制逐题确认描述不适用于当前v2流程。
- 下方“角色隔离”的 `sel_role` 自声明方式仅属于旧本机演示，当前公网学生入口不提供该模式。

## 实际收集的个人信息（2026-10-22 核对）

旧版本这里写过“只需昵称、不收集姓名和联系方式”，**已经不符合现状**。当前网页版收集：

| 信息 | 存在哪 | 用途 | 谁能看 |
|---|---|---|---|
| 姓名（允许化名）、手机号（未验证归属，可填家长号） | 注册表 `registry.db` 的 `student_registration`（明文，目录 0700、文件 0600） | 和找回码一起自助找回邀请码；管理员核对本人 | 管理员：`/admin/` 显示姓名 + 手机尾号 4 位；CLI `list`/`lookup` |
| 找回码（学生注册时自己设的 4 位数字） | 同上，只存加盐 scrypt 摘要；连续输错次数与锁定到期时间 | 自助找回邀请码 | 没有人能看到原文 |
| 同意记录：规则版本、同意时间、年龄段、监护人同意、所用注册码编号 | 同上（只有 2026-10-22 至 23 之间按旧流程注册的账号可能有；现在不再收集） | — | 管理员 |
| 试卷/作业/练习照片（可能带姓名、班级、分数），去 EXIF 后转 JPEG | 学生自己的目录 | 识别题目、练习核对 | 学生本人；照片发给阿里云百炼处理 |
| 题目、对错记录、反思文字 | 学生自己的 `app.db` | 错题本、延迟重做、掌握判断 | 学生本人；家长/老师只见聚合数字 |
| 录音 | 不落盘 | 转文字 | 发给百炼转写，本应用不保存 |
| 互动记录（时间、路由模板、按钮标识） | 学生自己的审计日志 | 排查故障 | 管理员 |
| 邀请码 | 只存 SHA256；另外每个用新码登录的会话保存一份**只有该会话令牌能解开**的加密副本（AES-256-GCM，密钥由会话令牌经 HKDF 派生，库里只有令牌哈希），用于学生在设置里查看自己的码 | 登录 | 只有登录着的那台设备 |
| 注册码（班级码，默认不用） | 只存 SHA256 与编号、备注、次数、到期 | 设了 `SEL_REGISTRATION_CODE_REQUIRED=1` 时限制谁能注册 | 管理员 |

## 注册、找回与告知（2026-10-23）

- 注册页 `/s/register`：填姓名（可化名）、手机号，自己设一个 4 位找回码（四位相同、顺着或倒着数的不收）。默认不要班级注册码；设了 `SEL_REGISTRATION_CODE_REQUIRED=1` 时还要老师/管理员发的 8 位注册码。同一姓名手机号不能注册两次，提示去找回。
- 找回页 `/s/recover`：姓名 + 手机号 + 找回码都对，就作废旧码和全部会话、当场发新码；对不上统一一句话，不说是哪一项错。同一账号连续错 5 次锁 24 小时（计数存在注册表里，重启不清零），另外按 IP 限速。停用的账号不能自助找回。
- 找回码只防「知道姓名和手机号的人」（比如同班同学）直接拿到新码；它不是短信验证，猜中 4 位数字的概率被锁定次数限制住。没设过找回码的老账号只能请管理员找回，登录后可以在「我的邀请码」里补设。
- 不再有《个人信息处理规则》页面、同意勾选和年龄选择（产品决定，2026-10-23）。注意：《个人信息保护法》对处理未满 14 周岁未成年人信息要求取得监护人同意并制定专门规则，正式推广前需要另行处理。
- 登录页、注册页识别微信等应用内置浏览器，给出“右上角 … → 在浏览器打开 / 在 Safari 中打开”的分步引导和一个「复制网址」按钮（2026-11-01 起；带着预填码进来时网址里连码一起带上），并提醒先保存邀请码。
- **预填码的登录链接**（2026-11-01 起）：`admin-cli create / invite / reset-invitation` 打印 `/s/?code=XXXX-XXXX-XXXX` 和可选的终端二维码，学生在「我的邀请码」里也能看到同一条链接和二维码（换手机用）。打开链接只显示填好码的登录页，学生点「进入我的错题本」才 POST 兑换；GET 永不建会话、不计限速，链接预览和误点不会把码用掉。已登录的手机打开带码链接也只看到登录页（说明会换账号），带码的查询串不转发给学生进程。码出现的地方只有：URL 查询串、登录页输入框的 `value`、微信「复制网址」按钮的 `data-copy-text`、「我的邀请码」页的链接文字与二维码、`/s/login?code=` 的 303 `Location`。不落日志的依据：Caddy 未开访问日志；应用的访问日志只记路由模板（`routeTemplate` 去掉查询串与片段）不记查询串；页面 `Referrer-Policy: same-origin`，Referer 最远只回到本站且不被记录；Set-Cookie 里只有随机会话令牌。面向老师的发放规则（一对一、不进群、发错即换码）见 [老师发码指南](../product/TEACHER_INVITE_GUIDE.md)。

## 管理员的账号操作（本机 CLI）

所有命令都要以服务用户运行并显式给出注册库目录，**没有设置 `SEL_STUDENT_HOST_DIR` 或目录不存在时 CLI 拒绝运行**（不再悄悄新建空库）：

    sudo -u supererrorlog env SEL_STUDENT_HOST_DIR=/var/lib/super-error-log/student-host \
      node /opt/super-error-log/current/dist/studentHost/admin-cli.js <命令>

- `registration-code create [--uses N] [--days D] [备注]`：生成注册码（缺省 60 人、14 天），明文只显示一次；`registration-code list`、`registration-code revoke <编号>`。只有服务设了 `SEL_REGISTRATION_CODE_REQUIRED=1` 时注册才要用。
- `lookup <姓名> <手机号>`（精确）或 `lookup <姓名片段 | 手机尾号4位>`（候选列表，姓名打码）。
- `revoke-sessions <ID>`：只踢下线，**不作废邀请码**，持码人可立即再登录。要封禁用 `disable`。
- `disable <ID>`：作废全部邀请码与会话，不能再登录，学习数据保留；`reset-invitation <ID>` 恢复并发新码。
- `delete <ID> --confirm`：删除注册资料、邀请码、会话和整个学生目录，不可恢复。要求先 `disable`，并且该学生没有正在运行的进程：每个学生进程启动时在自己的目录写 `.worker.pid`、退出时删除，CLI 据此判活（进程还活着、或标记文件无法识别时一律拒绝删除并说明原因）。被拒绝时：等进程空闲退出（缺省约 12 分钟，`SEL_WORKER_IDLE_MS`；有识别/打印任务在跑时会更久），或 `systemctl stop super-error-log` 停服后再删，删完再启动。`deletions.log` 只记日期和账号 ID。服务器备份里的副本要等备份过期才消失——回复删除请求时要如实说明。
- `export <ID> <输出目录>`：输出目录先解开符号链接再检查，落在注册库目录或学生目录里面（含经符号链接指过去）一律拒绝。导出 `account.json`（登记资料、同意记录、邀请码/会话元数据，不含任何码或令牌）和 `data/`（学生目录副本，SQLite 用 `VACUUM INTO` 取一致快照），目录 0700。核验本人后再交出，交完删除导出目录。

删除/导出请求的处理顺序：经老师核实身份 → `lookup` → `export`（如需）→ `disable` → 等进程退出（或停服）后 `delete --confirm`（还在运行时会被拒绝）→ 告知对方备份副本的过期时间。

## 数据最小化

- 注册只收姓名（可用化名）和手机号（见上表），不收学校、班级、身份证号；不发短信、不做实名核验。
- 上传内容包括错题照片/PDF及本次练习的作答照片；EXIF 元数据（含可能的 GPS 信息）在入库前被 sharp 剥离并统一转 JPEG。拍照前可以遮住姓名。

## 角色隔离

- 两个角色：学生（默认）与家长，通过 `sel_role` Cookie 切换。
- **重要边界**：角色为自声明、无口令（MVP 家庭自用单机假设，决策 D6）。该机制防误触、不防有意绕过——家长手动切回学生态即可看到全部内容。若试点中出现绕过行为，下一步加家长口令。
- 学生专属：题目原文、照片、反思、回传明细、媒体文件流。家长态访问一律 403（页面与 API 双层）。
- 家长可见：每周完成率、学科掌握度、薄弱知识点 Top5 —— 全部为聚合数字与标签名。

## AI 边界

- AI 做：题目提取、字段建议、练习作答转写与题号匹配、基于参考答案的初步核对建议。作答分析使用本次照片与冻结题面/参考答案；不自动提交作答结果或认定掌握。
- AI 不做：提交反思（服务端校验 `submittedBy='student'`，AI 提交直接拒绝；反思页的「一键采纳」是学生本人点击提交的主动行为，记录 `adopted_ai=1` 供采纳率监控）、自动归档、评价学生。
- mock 模式不发出任何网络请求；真实模式仅向配置的模型接口发送题目图片/文本。
- 掌握感（0–3 自评）永远不进入 AI 建议范围——它是「自评 vs 延迟重做结果」的校准信号，AI 代建议会污染该信号。

## 云端识别链路（iOS → study.pccoding666.com，2026-09-20 起）

- **上传前明示同意**：iOS 每批上传前展示所选照片张数与处理链路说明，不同意则不上传；照片原始字节只存本机，上传的是一次性生成的 JPEG 副本。
- **设备授权**：扫码配对（配对码单次使用、5 分钟有效）；兑换得到 30 天设备令牌，存本机 Keychain；管理员可随时按设备撤销（撤销后该设备请求一律 401）。
- **传输与入口**：全程 HTTPS（Let's Encrypt）；服务端有按设备限流、上传并发与容量门槛、磁盘水位门槛；无令牌一律 401。
- **服务器存储**：识别任务的原图与裁图存于广州 ECS `/var/lib/super-error-log`（专用系统用户私有目录，0750）。**当前无自动过期清理**——数据量受磁盘门槛保护；试点期如需清理，由管理员手动删除任务目录（数据保留策略待试点后拍板，见 RISK_REGISTER）。
- **第三方处理**：图片由阿里云百炼（DashScope 兼容接口，base64 内联提交，不走临时 OSS）做识别处理；服务商的数据处理以其条款为准，上传同意文案已告知学生/家长。
- **可核对性**：iOS 端任何 AI 识别结果必须对照本机原图逐项确认后才生效；服务器对未通过证据核对的内容不放行确认与打印。

## 学生网页版（Safari / 主屏幕，`https://study.pccoding666.com/s/`，2026-10-09 起）

在 iOS App 等 Apple 开发者账号期间，学生用 Safari 打开网页版并「添加到主屏幕」。网页版与 App 走同一台服务器、同一套 `/v1` `/v2` 业务规则，数据流差别如下：

- **配对与 cookie**：管理员 `admin-cli pairing-code` 生成的是同一个一次性配对码（5 分钟、单次使用），网页版用链接 `/s/pair?code=<配对载荷的 base64url>` 携带。打开链接只显示确认页，学生点「连接这台手机」才兑换（聊天软件的链接预览不会把码用掉）。兑换得到与 App 同一种 30 天设备令牌，存在 **httpOnly cookie `sel_device`**（`Path=/s`、`SameSite=Lax`、HTTPS 下 `Secure`；页面脚本读不到，也不发给 `/v1` `/v2`）。管理员 `devices` 里显示为「网页版 · iPhone Safari」，可同样按设备撤销。配对码在链接里出现一次：Caddy 未开访问日志，页面 `Referrer-Policy: same-origin`，兑换后立即跳转。
- **网页版的其他 cookie**（都在 `/s` 下、httpOnly，不含任何题目、照片、回答或名字）：`sel_photos`（本周照片的两个本机标记——「这页没有做错的题」「移除这张」——只存识别任务 ID）、`sel_skip`（本次打开里点过的「跳过」，会话 cookie）、`sel_a2hs`（看过「放到主屏幕」提示）、`sel_items_subject`（本次浏览错题本选择的学科，会话 cookie）、`sel_items_grade`（本次浏览错题本选择的有效年级，会话 cookie）。浏览器里可能还留着旧的 `sel_consent`，服务端不再读取、不再写入。另有一个**不是 httpOnly** 的 `sel_tap`（页面脚本写、120 秒、随下一个请求交给服务器后立即清掉）：只存「点了哪个按钮的固定标识 + 页面路径」，用于下面的互动记录。
- **互动记录**（2026-10-11 起，`docs/web-interaction-trail.md`）：每次看页、点按、提交、跳过、出错，写一行到现有的审计日志（`audit_event` / `events.log`），只有时间戳、路由模板（练习 / 题目 / 照片的 ID 换成占位符，不带查询参数和配对码）、动作标识、设备 ID。不记题目、回答、照片、名字、选了什么。
- **照片**：与 App 同一条链路（上传 → 广州服务器 → 阿里云百炼找题 / 读题）。差别：用网页拍照的照片**不会存进手机相册**，只存在服务器上（从相册选的原图仍在相册里）；服务器收到后统一转成 JPEG 并**去掉 EXIF（含可能的位置信息）**，再交给识别。网页上传不再单独弹出同意页，选好照片即上传；照片交给百炼处理这件事改在注册时由《个人信息处理规则》告知并勾选同意（见上文）。
- **语音（说说为什么错、改一下）**：App 在手机上本地转文字；网页版改为把这一段录音（≤ 60 秒、≤ 5 MB，iOS Safari 产出 `audio/mp4`）发到服务器，由服务器**原样转交阿里云百炼的语音识别模型（qwen-audio-3.1-asr-flash，经百炼原生接口，Base64 内联在请求里）**转成文字。**录音不落盘、不写日志、不进数据库**，转出的文字也不保存，只放回网页文本框——学生看过、可以改，自己点「说完了」才作为回答提交（AI 只转写，不替学生提交）。语音按钮旁有固定提示「录音会发给通义千问转文字，本应用不保存录音；最多 60 秒，也可以直接打字」。麦克风权限由 Safari 询问；不给权限、没有麦克风或网络失败时按钮旁说明可直接打字，已输入的文字不丢。mock 模式（测试与本地）不发出任何网络请求，固定返回一句合成文字。
- **离线**：Service Worker 只缓存外壳（离线页、样式、脚本、图标），**不缓存任何学生数据**；连不上服务器时只显示离线页。所有页面与图片响应都是 `cache-control: private, no-store`。
- **没有家长或管理页面**：`/s/` 只有学生自己的页面；云端仍不挂旧的 Web 看板（`/`、`/parent` 等照旧 404）。

## 纸上练习作答（2026-10-20）

- 作答照片保存于学生独立数据库的练习附件表，统一转JPEG并去掉元数据；不作为新错题导入。
- 每份练习最多12张，每张上传不超过15MiB；同一照片版本最多3次分析。题号不明、过程不完整或识别不清时保留待处理。
- 反馈由学生本人确认，可修改或暂不记录；实际日期和是否用过帮助由学生选择。照片收到、AI建议、学生结果和掌握判定是独立状态。
- 取消练习保留照片和已记录结果。照片与反馈不进入静态缓存，查看必须登录对应学生空间。

## 存储与删除

- Web 端全部数据在本地 `SEL_DATA_DIR`（SQLite + uploads/ + packets/）。
- 事件日志（audit_event / events.log）只记录动作与实体 ID，不记录题目内容或反思文本。
- 设置页"清空所有数据"物理删除数据库记录与上传文件，不可恢复。
- 学生邀请码网页版的账号删除、停用、导出见上文「管理员的账号操作」。
- iOS 端：照片与本机识别快照仅存设备本地（应用沙盒，排除云备份）；云端任务的删除走管理员通道。
