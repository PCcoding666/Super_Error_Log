# iPhone 云端识别：广州家庭试用版

日期：2026-09-17。状态：待用户审阅；本文件是设计，不代表服务已经部署或真机验收通过。

## 给使用者看的摘要

手机不再依赖 Mac 开机或同一 Wi-Fi。首次扫描一次配对二维码，以后选择照片、确认上传，就能通过云端调用真实 AI；不确定的内容仍须对照原图确认。

- 服务地址：`https://study.pccoding666.com`，使用用户已指定的广州 PC ECS。
- 保留服务器上的原有网站；本次只新增错题本服务，不购买或升级云资源。
- 中文界面明确显示“未连接、正在检查、可以上传、服务繁忙、连接失败”，并提供对应操作。
- 仅支持一个家庭的一份学习资料库。已配对设备能访问这份资料，不是多人账户隔离系统。
- 照片仍需每批明确同意。提示改为“上传到你的广州云服务器，再由阿里云百炼处理”。不自动迁移 Mac 的历史照片。
- 第一关：真机使用蜂窝网络上传一张真实照片并收到真实 AI 结果。之后再检查十张照片的批量稳定性，不能把域名解析成功当成应用交付。

## 1. 已确认事实与范围变化

2026-09-17 只读检查：广州 PC 为 2 核、2GB、3Mbps，观察时可用内存约 1.5GB、系统盘剩余约 32GB；这是当时快照，不是容量压测。SSH 可用，服务器到百炼的 TLS 校验通过，未认证请求返回 401，不等于模型推理已经验证。

原有 `wikiworldlife-board.service` 占用 80 端口，进程运行，但本次本机 HTTP 探测未获响应。该异常不在本轮修复范围。443 端口当时空闲、安全组已放行；部署前必须重查。未发现可直接使用的 Node 或 Docker 命令。

`study.pccoding666.com` 的 A 记录已新增，Google、Cloudflare 与 ECS 本机解析均指向广州 PC；原有主域名、`www`、`vidsnap` 记录未改动。用户已确认主域名在阿里云完成 ICP 备案，这是用户确认信息，并非本轮独立查验的备案记录。

本设计替代 `2026-09-17-iphone-lan-pairing-design.md` 的“仅同一 Wi-Fi、不开放公网”范围；旧文档保留为历史。保留其中明确上传同意、独立设备凭据、连接检查、任务归属与失败不丢数据的要求。不同时建设另一套局域网入口。

## 2. 方案选择

采用**已有 ECS 上的独立服务 + 标准 HTTPS + 手机扫码授权**。与现有 TypeScript 后端直接衔接，用户不需安装 VPN，也不需新购服务器。

对照方案：继续 Mac 局域网服务需要 Mac 常开且不能满足外出使用；新建更大云服务器增加资源与迁移工作，目前未有实测证据要求这样做。两个方案本轮均不采用。

请求路径是 iPhone → HTTPS 接入 → 私有识别服务 → 百炼北京接口。题目识别、图示提取、答案与订正转写、证据检查继续复用现有逻辑；不更换模型、不重开模型比较、不降低确认门槛。

## 3. 服务器部署与隔离

- 新增专用低权限系统用户、独立代码目录与私有数据目录。建议路径分别为 `/opt/super-error-log/releases/`、`/var/lib/super-error-log/`、`/etc/super-error-log/`；部署前检查有无同名既有资源，有冲突则停止，不覆盖。
- 使用 Node 24 LTS、编译后的移动后端与锁定依赖。构建和自动测试在本机完成；Linux 生产依赖在受控发布目录安装，不复制 macOS 的原生模块。安装包只含白名单源码构建产物、依赖清单和必要配置模板，不含工作目录、照片、历史实验、`.env`、签名资料或 Git 历史。
- 识别进程继续只监听 `127.0.0.1:3101`，由独立 systemd 服务管理。旧网页应用 3100 不部署为公网入口，不将角色切换 Cookie 当账户认证。
- 新增独立 Caddy 服务，只接管新域名的 TCP 443，关闭其 HTTP 重定向和 HTTP 证书挑战。用 443 的 TLS-ALPN 验证申请、自动续期可信证书，不占用原网站的 80 端口，不把阿里云管理 AccessKey 留在 ECS 上。
- 不启用任意域名即时签证书、静态文件目录浏览或公网管理 API。不开放 3101，不修改原网站、不升级全机软件、不重启 ECS。
- 百炼密钥仅在服务端受限配置中使用。手机、二维码、仓库与日志中都不出现云管理密钥或模型密钥。
- 部署前记录原有服务与端口基线。发布采用新目录、校验、切换和仅重启错题本的方式。保留上一版本；回滚不删除照片或回退到旧共享令牌的公网认证。数据格式变化须向后兼容或有经过验证的恢复步骤。

证书失败、端口冲突、依赖安装失败时停止该步骤，不关闭证书验证、不降级为公网 HTTP、不挪用原网站端口。

## 4. 配对与隐私边界

手机使用系统标准证书链及域名校验。本轮只接受 `https://study.pccoding666.com` 的云端连接，不接受二维码指定的任意服务器；开发测试仍可显式使用旧回环模式。禁止携带凭据的重定向，禁止自动回退为 HTTP。

管理员经已有 SSH 通道访问仅服务器本机可用的管理入口，生成五分钟有效、256 位随机秘密的单次配对码。二维码只在 Mac 上的受限本地文件展示，不由公网网页托管、不写入共享报告。二维码携带协议版本、服务 ID、固定 HTTPS 地址、配对会话及一次性秘密，不包含长期令牌。

手机扫描后显示“连接你的云端错题本”和目标地址，用户确认才兑换。兑换接口为有请求体限制与速率限制的独立入口；并发兑换只能绑定一个客户端请求 ID。同一客户端可在原有效期内恢复丢失响应，短期恢复响应仅保留内存；服务重启导致恢复不可用时需重新扫码。

每台手机获得独立随机访问令牌，30 天有效，可单独撤销。服务端落盘成功后才返回令牌，持久化只保存校验值、设备信息、到期和撤销状态；手机保存于仅本设备可用的 Keychain。所有任务、照片、裁图和确认接口逐次鉴权。旧共享令牌不得从云端公网入口使用。

初始速率限制：配对失败每来源 IP 每分钟最多 10 次、全局每分钟最多 60 次；普通鉴权失败每 IP 每分钟最多 30 次；已鉴权普通查询每设备每分钟最多 300 次。公网来源只信任本机反向代理明确覆写的地址信息，伪造转发头不可绕过限制。限流返回 429 与 Retry-After，不记录秘密。

本轮保留用户明确上传的 JPEG、必要裁图、任务和识别证据。云端不是公开相册。运维日志只记任务 ID、阶段、耗时与脱敏错误，不记照片、题干、答案或凭据。私有识别证据与公开运维日志分开保存。

发布前对已有云端状态做本机受限备份，备份不通过 HTTP 提供；这只用于发布恢复，不能宣称异地灾备。暂不新增 OSS 或其他备份服务，不自动把云端照片复制回 Mac，不自动清理用户资料；达到存储安全阈值时停止接收新任务并提示管理。

## 5. 2GB 机器的资源保护

- 初始只运行一个整页识别任务，逐题并发从现有 2 降为 1。上传解码与图示裁切使用同一有限的图片处理通道，不能只限制模型请求却让图片在入口无限并发解码。
- 同时最多接收一份上传正文，额外上传立即返回可重试的繁忙状态，不在内存排队保存图片请求。认证与入口容量检查先于大请求体解析；反向代理也设置正文与读取时限。
- 待处理容量最多 10 张照片（含运行中的任务）；重试占用同一容量体系。幂等重传保持同一任务，相同键不同内容仍报冲突。容量满时不接受一个实际无法安排的“成功任务”。
- JPEG 上传上限统一为 15,000,000 字节（与现有手机端一致），保留 4000 万像素边界，不为了内存偷偷裁掉题干或强行降清晰度。限制 sharp 缓存与并行处理，并用实际大图压力测试确定安全性。
- 初始目标为识别进程组内存高水位 768MiB、硬上限 1GiB、CPU 上限为 1.5 核；先验证系统支持与失败恢复，再启用这些限制。它们是保护设置，不是已测得的峰值。若最大合法照片无法在限制内处理，不能宣称通过，需要调整策略并重新验收。
- 系统盘可用空间小于 3GiB 或错题本数据达到 10GiB 时拒绝新上传，不自动删除已有照片。队列持久化状态、单进程写入和安全关机沿用现有机制；重启后明确显示中断及主动恢复，不把丢失的工作冒充完成。
- 长期累计历史目前尚未做大规模容量验证。试用阶段监测任务元数据内存，不能把十张图通过推广为无限历史或多人容量承诺。

## 6. iPhone 交互与连接状态

连接设置改为“连接识别服务”，主入口为扫码；不要求学生输入长令牌。首页与上传确认页提供“检查连接 / 重新配对”，不只有灰色按钮。

状态独立于配对配置：未配对、已配对待检查、检查中、可以上传、服务繁忙、连接失败、授权失效、版本不兼容。配对成功、切回前台、打开上传确认页可触发轻量检查，合并并发检查；检查不上传照片、不调用收费模型。

健康接口在认证后返回协议版本、持久化服务 ID、存储可用、识别配置就绪及接收新任务能力。检查通过只说明连接、授权和入口就绪，不保证下一次模型调用一定成功。最近检查有效期 30 秒，开始每批上传前再次检查；后台、切换服务、网络请求失败与授权失效立即清除旧的可上传状态。

上传确认页说明目的地已从 Mac 改为广州云服务器，以及会由百炼处理。同意绑定照片集合与服务 ID，不沿用旧 Mac 的上传同意。序列上传已同意的照片，显示逐张提交/排队/识别/待核对/失败，而不是整批只显示一个转圈。

连接检查超时与上传、任务处理超时分开。上传允许最长 180 秒资源时限，并显示超时可重试；异步识别返回任务后独立轮询，不让一个 HTTP 请求等待整道题完成。任何重试复用已保存的上传副本及幂等键，不能自动重新调用模型直到成功。

所有任务与媒体缓存增加明确的服务归属。旧 Mac 来源未知或不同的任务保留为离线可查看，不自动向新服务查询、重传或混并；当前云端重新配对后仍可继续同一服务的任务。切换配对时取消旧请求，并检查迟到响应的服务版本，避免污染新连接状态。

本地照片、学生反思、原文语言与练习包不因更换连接而丢失。AI 仍只能提建议，学生自行完成反思；失败或证据不完整的题目不可进入正式确认与打印。

## 7. 模块边界

- 服务连接配置：区分原有回环开发模式与显式云端模式，校验域名、代理和密钥来源。
- 配对与认证模块：管理入口、短期兑换、设备令牌、限流与撤销；不夹在识别算法里。
- 入口容量模块：正文限制、上传槽位、图像处理并发、任务容量、存储安全阈值。
- 识别模块：复用现有清单、逐题处理、证据检查、主动重试与确认规则。
- 发布模块：白名单制品、Linux 依赖、专用服务、TLS、检查、回滚，不修改既有业务。
- 手机连接控制器：安全解析二维码、配对、真实检查与状态失效；StudyStore 管理服务归属和用户明确操作。

## 8. 验收与交付顺序

1. 本地先写失败测试再实现：过期/重放/并发配对、撤销、错误主机及证书、重定向、伪造代理头、未认证媒体访问、令牌脱敏、服务切换及迟到响应。
2. 验证限流、队列满、超大/损坏图片、并发上传、幂等冲突、磁盘不足与中断恢复。十张合成高分辨率照片用于资源压力测试，不当成真实题目质量结果。
3. 运行 `npm run verify`、Swift 自动测试、相关原生 UI 测试和真机目标构建。记录无法执行的测试，不用其他测试替代。
4. 广州部署前重查端口与资源，部署后检查标准 TLS、无令牌访问拒绝、授权健康检查、媒体保护、内存与磁盘。原网站不重启，独立核对其既有服务与端口仍保留，不把其已有 HTTP 故障说成已修复。
5. 更新同一 iPhone 应用，保留数据。用户扫码连接，在蜂窝网络下明确同意上传一张真实照片；核对手机提交、ECS 任务、真实百炼返回和手机结果四方对应。合成响应与离线脚本提交不能替代这一步。
6. 一张真实照片通过后，手机端再运行用户明确选定的十张照片。报告每张实际结果、失败/恢复及人工内容确认，保留失败证据，不把所有 HTTP 成功当成识别准确。
7. 在无正在执行的真实任务时验证断线、恢复、单设备撤销与错题本服务重启。不得为测试停止原有网站或丢弃用户照片。
8. 最终分别报告域名、HTTPS、授权、上传、真实返回、内容质量、故障恢复。仅将代码、测试与脱敏文档推送既有 GitHub 开发分支，不推送私有制品或密钥，不强推。
