# 学习材料收录、关联与按需批改

日期：2026-10-20（Asia/Singapore）。状态：用户已认可对话中的方向；本稿整合三项批注，供实施前评审。本文描述拟新增能力，不代表已经实现或上线。

## 1. 已确认的目标

学生可以先拍题目、答题卡、作业本、批改结果或答案页，顺序不限，之后还能补充。系统把相关材料关联到同一道题，保留学生原始作答，再支持批改、错题收录及延迟复习。

学生主动发起收录、补充或批改；具体逐题关联由系统完成。有充分依据时自动处理，有歧义时只询问影响关联的少量问题。收录本身可以独立结束，不要求当场选练习或完成复盘。

本轮用户批注落实：

| 批注 | 确定的设计 |
| --- | --- |
| 参考答案也可以是 AI 生成的 | 保留“提供的参考答案”和“AI 参考答案”及各自来源、版本，允许同时存在；生成答案不会覆盖原始作答 |
| 认可自动关联，细节上线再打磨 | 确定自动关联、歧义询问、改关联及撤销的基本行为；按钮位置、文案、候选排序在试用中调整 |
| 拍照时可以加标签，不必框定 | 提供可选“加标签”；不要求固定拍摄顺序、先选材料类型、先分组或逐题框选 |

“老师已批改”是支持的一种情况。未批改、部分批改、没有参考答案也能先保存。

## 2. 范围及当前实现的变化

当前手机网页 `/s/` 主要按单张照片建立识别任务，再把识别出的题接入错题本。`src/ai/evidence.ts` 已区分作答、订正、批注和参考答案，但其区域仍依附该照片；`src/bridge/recognitionToItems.ts` 主要按识别任务与题目关联学习记录。

本轮增加“先收材料、再按题关联”的能力，复用现有上传兼容处理、识别队列和学生隔离。网页仍是主要入口，iOS 不在本轮改造范围。

本轮范围包括连续采集与相册多选、可选标签、跨照片关联、后补材料、手工答案、AI 参考答案、用户发起的 AI 批改、错题本衔接。先后交付可以按依赖拆分，完整验收必须覆盖这些能力。

变式题、开放注册、家长明细、自动连接学校阅卷账号不属于本轮。人工导入的批改截图属于可接收材料。

早期设计中“无批改痕迹先手选，AI 不判断对错”的范围按本次用户意见调整为“先保存材料，按需请求 AI 批改建议”。学生本人反思、延迟独立重做才更新掌握状态、家长仅见聚合数据等规则继续保留。

## 3. 学生流程

### 3.1 拍进来

- 默认入口为“拍照 / 从相册选”，首次上传说明继续保留；日常入口避免重复点击同名“拍第一页”。
- 拍摄页持续提供拍下一页、已拍数量和“拍好了”。相册支持多选。
- 页面短提示：“题目、答题卡、作答或答案都可以拍，顺序不限，之后还能补。”
- 采集与上传解耦：一张进入上传队列后可以继续采集；每张显示待上传、上传中、已保存或失败。
- “拍好了”结束本次采集，不等于所有照片已到服务器。仅在服务器确认后显示“照片已保存，可以先离开”。

### 3.2 可选标签

“加标签”是可跳过的辅助入口，既可在拍照时添加，也可在拍完后批量补充。

- 材料提示示例：题目、答题卡、我的作答、答案页。
- 状态提示示例：未批改、已批改、部分批改。
- 归属提示示例：数学周测、某次作业；也可选择已有的一份材料。
- 标签可修改或移除，不加也能保存。既有识别结果不会因为后来添加标签而被无声覆盖。
- 类型标签是提示，一张照片仍可同时包含题目、作答、批改及答案。批改状态最终按题保留。
- 相同自由标签不等于同一份试卷；用户明确选中已有材料记录，比名称相同提供更强的归属依据。

### 3.3 看整理结果

结果按题组织，不要求逐张进入、逐题确认。默认显示题号或可识别的题目摘要，以及已找到、待补充、待确定的材料。

例如仅收到一张答题卡：

> **第 12 题**
>
> - 你的作答：已找到
> - 老师批改：扣 2 分
> - 题目：待补充
> - 提供的参考答案：未提供
> - AI 参考答案：待补题目后可生成
>
> 操作：补充材料 / 输入正确答案 / 查看原图

没有证据时不显示“老师扣分”之类推断。题干缺失时仍保留材料和临时题记录；补入后更新同一记录。

批次可以显示“已保存 4 页，整理出 12 道题，有 1 处需要确定对应关系”。学生可先离开，之后继续。

### 3.4 补充、批改与练习

- “补充材料”支持继续拍照或相册导入；从一道题进入时自动带上该题的关联上下文。
- “输入正确答案”支持单题文字输入；批量粘贴按题号列出的答案时，无法唯一对应的部分单独处理。
- “生成参考答案”支持一道题或一批具备完整题干的题，明确标为 AI 生成。
- “帮我批改”由学生主动触发，支持选定题或整份材料中符合条件的题。
- 已有批改结果可以用于错题收录；学生也可主动标为错题、取消或撤销。AI 批改建议单独标明来源，不能冒充老师批改。
- 保存材料之后可结束；“安排本周练习”是后续独立动作，沿用推荐预选、一次接受的交互。

## 4. 关联规则

关联对象包括题干与图形、原始作答过程、订正、批改和参考答案。它们可以来自一张照片的不同区域，也可以跨多张照片；一张答案页可服务多道题。

系统利用试卷标题、学科、日期线索、页码、题号及小问、题目内容和用户标签寻找对应关系。拍摄先后与同一采集批次只是辅助信息，不强制把一次拍摄中的所有图片认成同一份卷子。

首版自动关联需要同时满足：

1. 归属有明确依据：用户指定了材料记录，或识别到足以区分已有候选的文档信息；
2. 完整题号与小问、材料角色等信息兼容，候选唯一；
3. 没有其他文档、内容或作答次数冲突。模型自报置信度不能单独作为自动关联依据。

依据不足时保留待关联状态，并给出少量候选。示例：“这张答题卡对应哪份卷子？”配候选原图及名称。一次文档归属选择可作用于整张答题卡；其中仍有歧义的题继续保留待处理，不能一并强行匹配。

已关联材料提供“关联错了，换一下”和撤销。学生无需手动框出每道题才能修复关系；必要时允许指出题号或原图区域。

同题的再次作答属于新的作答记录；系统不得只因题干相同就把两次作答合并。跨日补拍可以补全旧记录，也可以建立新作答；无法区分时针对这一点询问。

## 5. 参考答案与批改

### 5.1 参考答案来源

每个答案记录保留来源类别、内容、关联题、小问范围、版本及生成或录入时间。

| 来源 | 展示与保留规则 |
| --- | --- |
| 拍照／导入的答案 | 保留原图区域；能识别来源时展示老师或答案册，来源不明时显示“导入答案” |
| 学生手动输入 | 标为“手动提供”；学生可注明是老师提供，不据此冒充经过系统核验 |
| AI 生成 | 独立显示“AI 参考答案”，保留所依据的题干版本及模型信息 |

答案页后到时不删除已经生成的 AI 答案，AI 答案也不覆盖人工答案。相同答案可折叠展示来源；相互冲突的答案并列保留，并只对受影响的题提示选择使用依据。

默认采用唯一且无冲突的用户提供答案作为批改参考；没有提供答案时可以生成 AI 参考解答。AI 结果始终标明来源，不能因为展示在“参考答案”区域就变成已核验的正确答案。

### 5.2 按需批改

批改前检查所选题的题干、必要图形、对应作答是否足够完整，且关联无歧义。缺少信息的题保存为待补充，其余合格题继续处理。

批改记录引用具体作答与答案版本，结果可以是正确、部分正确、错误或无法确定，并给出能回指原作的简短依据。没有评分标准时不承诺精确扣分。

“未批改”是状态；“帮我批改”是操作。新拍照片、加标签或输入答案本身不自动触发整份 AI 批改。

批改动作需要生成参考解答时，可作为该请求的一部分生成，界面说明使用了 AI 参考答案。材料内容中的指令仅当作材料，不得改变系统规则。

老师判断与 AI 判断分开保留。AI 不改写原始作答，也不代替学生提交反思；批改正确不会直接增加掌握度。

## 6. 数据及组件边界

使用新增的关联层组织材料，不把无题干的答题卡硬塞进当前要求完整题干的单图证据结构。

| 对象 | 职责 |
| --- | --- |
| 采集批次 | 记录一次采集及上传进度；与“一份试卷”分开 |
| 原始材料 | 学生归属、文件、上传状态、标签、识别版本；原图不可被 AI 输出覆盖 |
| 材料片段 | 图中区域及角色、识别文字、题号线索、来源材料；支持一图多角色 |
| 文档归属 | 一份试卷或作业的逻辑归属，可待确定；保留文档级关联依据 |
| 题目记录 | 稳定题目 ID、题干与图形；允许暂缺题干、小问结构及之后补全 |
| 作答记录 | 同题的一次作答，关联多个过程片段；原作、订正和重做分别保留 |
| 关联记录 | 来源片段与目标对象、自动或人工决定、依据、状态和版本；支持改绑与撤销 |
| 参考答案／批改记录 | 区分来源，引用题目、作答及答案版本；允许并存、待确定和过期 |

处理流为：保存材料 → 识别类型及片段 → 找到文档与题目候选 → 自动关联或局部询问 → 汇总题目状态 → 按需生成答案／批改 → 衔接错题本。

职责分离为采集与上传、材料提取、关联、答案与批改、学习记录适配五部分。后续任务拆分再确定模块文件，不把全部行为继续堆进现有网页路由。

旧题保留原有 ID、媒体和学习记录，旧单图来源映射到新关联层。已有错题与新题保持唯一关联，重复上传或重复处理不会新建多份错题。不重跑真实学生全部材料来完成迁移。

## 7. 恢复、变化与隔离

- 继续保留 HEIC/JPEG 归一化、最长边 4096、服务端限制、超时、重试和幂等约束。
- 连续采集采用浏览器待上传队列，限制同时处理的大图数量。成功上传后清理本地副本；失败项可重试或删除。
- 待上传队列与当前学生隔离。页面关闭可能暂停上传，不能承诺浏览器关闭后继续工作；重新打开后恢复未完成项。存储不足时明确提示，回退为单张上传。
- 初次上传说明同步说明待上传照片会临时保存在当前浏览器。退出或切换账号前处理尚未上传的草稿，避免遗失或暴露给另一个账号。
- 服务端保存的材料、关联和待处理状态不依赖本周 cookie，支持跨日继续。继续使用现有独立学生空间与访问校验。
- 题干、关联或答案变化后，使依赖旧版本的 AI 答案及批改标为过期；刷新页面不自动产生付费重算。学生明确重新生成或重新批改时使用新版本。
- 部分失败不阻塞其他照片或题。失败重试只处理相应阶段，保留既有识别请求预算和可恢复性判断。
- 已打印练习保持快照，不能因后来补答案而悄悄改变历史题面或评分依据。新练习使用当前有效版本。
- 缺失或关联未确定的材料可保存，但不能作为已完整核验的证据进入自动批改、诊断或打印。低置信结果按现有 v2 原图保留和打印警示规则处理，不新增强制逐题校对流程。

## 8. 验收与试用

以下都是行为验收，不代表已经达到的准确率或耗时。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 完全不加标签，题目与作答同页 | 正常保存、识别、关联，不要求手动分类 |
| 拍摄时加“答题卡／未批改／数学周测”标签 | 标签可选、可改，帮助关联且不把照片限制成一种角色 |
| 先拍答题卡，乱序补题目，跨日补答案 | 同一题记录逐步补全，原始作答保留，不重复建错题 |
| 先拍题目，再补作答；或一次全部导入 | 同样成立，不将上一行顺序设为必经流程 |
| 两份卷子都有第 12 题 | 不只按题号误合并；提供有区分依据的候选，支持整张归属确认 |
| 解题过程跨页、一道题含多个小问 | 相关片段可以共同组成一次作答，不丢小问对应关系 |
| 同题第二次作答 | 新作答与原始错误、订正分开保存 |
| 手工输入答案、拍答案页、AI 生成答案 | 三种均可用，来源可见，后来的版本不覆盖其他来源 |
| 提供答案与 AI 答案冲突 | 保留各自内容和来源，受影响题不静默完成确定性批改 |
| 已批改、部分批改、未批改混合 | 按题显示状态；学生可请求批改符合条件的题 |
| 缺题干／作答／必要图形 | 仍能保存，只提示补所缺材料，不输出无依据的批改结论 |
| 关联错误、撤销、页面刷新及并发更新 | 改动可恢复，旧版本结果不能覆盖新关联 |
| 上传超时、重试、刷新及浏览器重开 | 进度与实际保存状态一致，不重复建材料；待上传项可恢复 |
| 已有错题、打印与延迟重做 | 历史学习记录、快照和掌握规则不被破坏 |
| 两个学生的同题、同标签、同文件 | 仍完全隔离，不发生跨学生关联或内容访问 |

点击目标：无需修正的题不新增逐题确认；可选标签为零必需点击；一张答题卡的归属问题尽量一次确认整张；多页补选支持批量完成，不逐页回列表。正常采集结束可直接看到保存／整理状态，不必经过“勾出做错的题”中转页。

试用记录主动操作耗时、页面往返、点击和滚动，以及错关联、漏关联、撤销、待补材料恢复成功情况。不能只以点击更少判断体验更好，也不能把合成模型结果当真实识别准确率。

具体按钮排布、标签推荐、候选排序和提示文案在试用中调整。来源区分、原作保留、学生隔离、可恢复关联和不虚报保存成功属于交付条件。

## 9. 实施顺序与本稿交付状态

依赖顺序：材料与来源记录及旧数据兼容 → 连续采集和可选标签 → 跨图关联及修复 → 手工与 AI 参考答案 → 按需批改及错题本衔接 → 手机流程和旧闭环回归。

这是实施顺序，不改变本轮约定范围。实际发布需按当次发布授权执行。

本次仅固化设计，未修改产品代码，也未调用真实模型处理学生材料。完整设计稿评审后再形成具体实现任务和验证计划。
