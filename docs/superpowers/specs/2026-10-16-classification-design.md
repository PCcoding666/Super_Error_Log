# 错题学科与知识点分类

## 已确认的目标与交付方式

面向初中，默认数学、物理、化学；学科可改名、新增。AI 同时识别学科及一个或多个知识点，优先匹配统一目录，允许人工调整。查看错题按学科、知识点筛选并展示数量。历史错题需要批量补齐，保留人工确认结果。按学段组织分类，为高中等后续学段保留结构。

用户于 2026-10-16 确认设计，并要求按五个 PR 实施，每个验证、合并、发布后汇报，供其检查。该指示授权逐项交付；不引入新的设计审批步骤。保留现有手机网页、上传与学习闭环；不要求每题强制校对。

## 数据与行为

- 学段使用稳定 ID，当前默认 `junior`（初中），界面不增加学段选择。
- 每个学生维护独立目录；保持生产上每学生独立 worker/SQLite 的隔离方式，表内也约束归属。
- 学科、知识点用稳定 ID 关联错题；标准学科键与展示名分离，改名不影响 AI 理解或历史关联。
- 初中种子目录包含三科常见知识点及别名，不绑定教材章节。种子目录是初始版本，不宣称覆盖全部教材。后续维护目录不因重启或读取而恢复原名、重新生成已合并的分类。
- 一题属于一个学段、一个学科，可有多个知识点；知识点必须属于同一学科。无法归类保留待确认状态，不允许生成指向不存在目录的关联。
- 学科与知识点分别记录来源（AI/人工）和人工确认状态，后续 AI 写入必须保护人工结果。
- 现有 `error_item.subject`、`knowledge_tags` 等字段和学习状态保持兼容。PR1 不自动重写旧题，不调用真实 AI。
- 修改单题分类只影响当前题；目录改名和合并通过稳定关联作用于所有相关题目。PR2 实现事务化更新旧展示字段。
- AI 结果在录入/历史整理时持久化，列表查看不调用 AI。学生提前选科时，以其选择为准。
- 拍照时的手动选科以照片任务关联持久保存，在异步识别尚未建题时也不能丢失；识别建题后再用于单题分类。
- 历史整理使用持久化批次/任务，分批、可重试、可恢复；重试不重复修改已完成项，不覆盖人工确认。

## PR 边界

1. 分类结构、初中种子目录和兼容性验证；为人工优先和历史任务预留持久化字段。
2. 目录管理与手动归类，接入 `/s/` 当前表单、设置页。
3. 新题 AI 归类，复用统一目录并保护人工选择。
4. 错题列表筛选、数量与待确认入口。
5. 历史任务、进度、重试和人工保护。

## 发布约束

从最新 `origin/main` 建 `codex/<task>` 分支，PR 对 `main`。每项运行 `SEL_AI_MODE=mock npm run verify`，审查后合并，核实 Actions 与实际发布结果再汇报。

`deploy/ci/README.md` 明确：数据库迁移入口变化时“自动发布会提前拒绝，须安排人工发布和迁移验收”，且“禁止把迁移藏在其他入口绕过检查”。PR1 的新增表属于此类，需要管理员发布能力；不改保护、不将无法完成的发布报告为上线。当前 Cloud 未配置生产 SSH；已向用户询问可用管理员入口。该约束不妨碍完成实现、验证、打包及 PR 审查。

## 验收重点

兼容升级和重复启动；历史错题、证据及学习状态不变；改名不丢关联；跨学生/跨学段/跨学科关联被拒绝；人工结果不被覆盖；目录初始化不复活已调整条目；分类删除随合法数据删除清理；批次任务的归属和重试记录能持久保存。
