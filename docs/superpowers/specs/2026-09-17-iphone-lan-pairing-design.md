# iPhone 与 Mac：同一 Wi‑Fi 下的安全连接

日期：2026-09-17。状态：设计稿，待用户审阅；尚未实现、更新手机或完成真机验收。

## 给使用者看的摘要

本轮解决“应用能打开，但手机不能把照片发给 Mac”的问题，不重做模型比较或题目识别算法。

- iPhone 和 Mac 在同一个可信 Wi‑Fi 下使用。用户已确认此范围，并表示两台设备已连接同一 Wi‑Fi。
- Mac 启动识别服务并显示临时二维码；手机在“连接 Mac”里扫码、确认电脑，再检查连接。
- 不要求手填长口令，不在手机放百炼密钥，不开放公网入口。
- “已配对”和“现在可以上传”分别显示。连接检查不上传照片，也不发起收费模型调用。
- 上传仍须逐批明确同意。断线保留照片、任务与结果，不偷偷重传到另一台电脑。
- 最终用用户的真实 iPhone 验证：扫码连接 → 明确同意上传一张照片 → 收到真实识别结果。

当前安装版仍然只能连接回环地址，连接同一 Wi‑Fi 本身不会改变旧版限制。需要更新 Mac 服务和手机应用。

## 1. 范围与选择

选择“局域网 HTTPS + 扫码绑定 Mac 身份 + 手机专属访问凭据”。

比较过的路径：

1. **扫码配对（采用）**：一次扫码携带地址、电脑身份和短期配对凭据，减少用户输入；需要增加扫码和配对生命周期。
2. **手填 HTTPS 地址与凭据**：实现入口较少，但用户仍需辨认地址、传递凭据和核验电脑；不作为本轮主入口。
3. **公网中转或 VPN**：能够跨网络，但引入部署或额外软件与权限；超出已经确认的同一 Wi‑Fi 范围。

这是单个使用者、单个 Mac 学习资料库的连接功能，不是学生账户系统。配对手机具有该资料库的访问权限；二维码页与手机确认页须说明这一点。本轮不新增多人隔离、云同步、后台常驻上传、路由器端口映射或新 Mac 原生应用。

旧网页服务不开放到局域网。原有模拟器回环入口保留；局域网入口必须显式启用。

## 2. 学生交互

### 首次连接

1. Mac 端用本项目的本地启动/配对命令，选择当前 Wi‑Fi 对应的本机私有 IPv4 地址。已有服务不因查看页面自动重启。
2. Mac 生成仅本机可读的配对二维码页，标明电脑名称、地址、有效期，以及“持有此二维码可以配对并访问本人的学习资料”。页面不是公网网页。
3. iPhone 点“连接 Mac → 扫描二维码”，在需要时请求相机和局域网权限。不在启动应用时抢先请求权限。
4. 扫描后显示电脑名称与地址，用户点“连接这台 Mac”。扫码本身不上传照片。
5. 完成身份核验、配对和服务检查后，显示“已连接 · 可以上传”。失败时保留原有连接，不以不完整配置覆盖它。

二维码失效后，在 Mac 重新生成；不要求用户复制密钥。第一版 Mac 管理入口为本地命令和私有二维码页，设备列表与撤销也通过本机管理命令完成。

### 日常使用

- 首页和上传确认页均可进入连接设置。未连接时提供“连接 Mac / 检查连接”，而不是只有灰色上传按钮。
- 切回前台、保存配对后、打开上传确认页时可做轻量检查；并发检查合并，不持续高频探测。
- 最近检查在 30 秒内且当前应用在前台，才展示“可以上传”；开始每批上传前再次检查。
- 进入后台、改变配对、请求失败或收到撤销响应时，立即使可上传状态失效。批次正在进行时显示实际任务状态，不用“检查成功”伪装成上传成功。
- 检查通过不能保证下一秒网络仍可用；上传错误必须保留照片和幂等键，允许用户主动重试。
- 同一已同意批次中的每张照片独立提交，不扩大用户已选的照片范围。

### 状态与提示

| 状态 | 含义与操作 |
| --- | --- |
| 未配对 | 提供“连接 Mac” |
| 已配对，待检查 | 已保存凭据，但尚未证明服务当前可用 |
| 正在检查 | 验证身份、授权、协议和服务可用状态，不调用模型 |
| 已连接，可以上传 | 本次检查通过并带检查时间 |
| 暂时无法连接 Mac | 请检查同一 Wi‑Fi、Mac 是否醒着、服务是否启动；可重试 |
| 需要局域网权限 | 仅在系统提供足够证据时这样提示，并提供系统设置入口 |
| 配对已失效 | 重新扫码；不循环重试收费请求 |
| 电脑身份不匹配 | 停止请求，不提供“忽略并继续” |
| 服务未就绪 / 版本不兼容 | 给出对应说明，不启用上传 |

不能仅凭一个超时就断言用户拒绝了权限或 Mac 正在休眠；无法区分时使用准确的通用连接提示。

## 3. 连接与安全边界

### 网络入口

- 原有回环 HTTP 入口继续只监听 `127.0.0.1:3101`。
- 新局域网 HTTPS 入口默认端口 `3102`，仅显式启用后监听用户选择的、本机网卡实际拥有的 RFC1918 私有 IPv4 地址。
- 第一版不使用 `0.0.0.0`、公网 IP、任意域名、IPv6 或自动创建隧道；不修改全局代理、防火墙或路由器配置。
- 局域网入口拒绝不属于所选网卡子网的来源。子网检查只限制暴露范围，不替代加密和认证；不信任客户端传入的代理头。
- Wi‑Fi 地址变化、监听失败或网卡消失时，不自动切到其他网卡或明文服务。显示需重新选择地址/配对的操作。
- 同一 Wi‑Fi 若启用了访客隔离，仍可能不互通；报告实测结果，不承诺仅凭 Wi‑Fi 名称即可连接。

### Mac 身份与加密

- Mac 持久化随机服务 ID、专用 TLS 私钥和证书，存放在忽略版本控制的私有目录。目录权限 `0700`、敏感文件 `0600`；拒绝不安全符号链接，写入采用原子替换。
- HTTPS 最低 TLS 1.2。证书包含实际连接 IP 的 SAN、有明确有效期；私钥不进入二维码、日志、安装包或 Git。
- 二维码传递证书 SHA‑256 指纹。手机在发送配对秘密或访问令牌前，必须核对 TLS 对端证书与扫码所得指纹，并检查证书有效期、用途和目标地址。
- 信任仅限本应用保存的这个具体 Mac 身份。不安装系统根证书，不关闭系统安全设置，不接受所有自签名证书，不禁用主机名验证。
- 不跟随任何携带凭据的重定向，不回退为局域网 HTTP。旧回环 HTTP 仅保留给 Mac/模拟器兼容路径。
- 证书或服务身份改变需要重新扫码；不能在连接失败时自动信任新身份。若 iOS 的系统传输策略要求补充配置，只允许经验证的最小局域网例外，不加入全局任意网络放行。

### 配对生命周期

- Mac 本地管理命令通过只绑定回环的管理接口操作；管理凭据与现有识别令牌分离，不能通过局域网管理设备。
- 管理凭据不放 URL/query、进程参数或日志。CLI 从受限本地文件读取，在认证请求头中使用；管理接口不启用跨域访问。
- 每次配对生成 256 位随机秘密，有效期 5 分钟；只在内存中保留其校验值，重启后失效。生成新码会使旧未使用码失效。
- 二维码内容包括协议版本、`serverId`、显示名称、HTTPS 地址、证书指纹、会话 ID、短期秘密和过期时间。不包含百炼密钥或长期手机令牌。
- 手机确认后在已核验的 TLS 连接上兑换凭据。服务校验有效期、单次使用和有限请求体，并限制全局与来源的失败尝试速率；二维码不是无限试错的短数字码。
- 服务为该手机签发独立的 256 位随机访问令牌。服务端只持久化令牌校验值、设备 ID、显示名、创建时间、到期时间与撤销状态；手机令牌保存在 `WhenUnlockedThisDeviceOnly` Keychain 项中。
- 手机令牌有效期 30 天，到期须重新扫码；Mac 可以随时撤销单个设备。所有资料接口逐次验证到期与撤销，不能只在连接检查时验证。
- 配对兑换对同一个客户端请求 ID 幂等：短期内允许同一兑换恢复丢失响应，不能把同一二维码兑换成第二台设备。恢复响应只留内存，且不超过二维码原始有效期；服务重启或手机持久化失败后，明确提示重新扫码，不谎报成功。
- 设备记录必须成功落盘后才能返回成功。旧模拟器共用令牌在局域网入口无效；未认证请求不能读取照片、任务列表或服务配置。
- 二维码页与包含秘密的测试产物只保存到受限且 Git 忽略的位置。分享页面、截图和报告不得带上实际二维码或凭据。

## 4. 服务与客户端结构

保留当前题目识别、证据门槛、重试和确认接口语义，不改变模型选择或错误归因规则。

### Mac 端

- 连接配置模块：区分 legacy loopback 与显式启用的 LAN HTTPS，校验地址与证书。
- 配对存储模块：设备凭据、过期、撤销、配对会话和原子持久化。
- 本地管理模块：创建二维码、查看设备、撤销设备；只能从回环管理入口访问。
- 两个认证边界复用同一个识别服务实例，避免同时打开同一数据目录并启动两套任务处理器。
- LAN 入口增加专用配对兑换接口；现有 `/v1` 资料接口使用手机令牌鉴权。管理入口不能因为反向代理头或来源伪装而从 LAN 被访问。
- 认证后的健康接口返回契约版本、服务 ID、真实识别配置状态和存储可用状态；不回传密钥、环境变量或原始模型响应。

### iPhone 端

- 扫码解析与校验独立于照片导入，二维码文本设长度上限并严格校验格式、地址和协议，不执行二维码中的 URL/命令。
- 安全传输模块负责证书核验、禁止重定向和认证请求；不散落到各页面中。
- 配对模型显式区分旧模拟器配置和新 Mac 身份。已有 Keychain 数据兼容读取；旧配置在真机上提示重新扫码，不静默删除。
- 连接检查控制器独立管理状态、检查时间和当前配对版本。切换配对后，旧请求的迟到响应不能把新连接标为可用。
- 上传许可关联当前服务身份及所选照片。换 Mac 后必须重新确认，不能沿用对旧目标的同意。
- 已有任务保留其服务归属。不同服务的任务、幂等键和媒体不能混用；未知来源的旧任务保留为离线只读，不向新 Mac 自动查询或重传。
- 服务相同但凭据重新配对时，仍可继续该服务已知的任务；撤销和连接失败不删除本机照片、题目快照、反思或 PDF。

## 5. 验收

### 自动化安全与回归

先增加失败测试，再实现；至少覆盖：

- 默认仍是回环、不允许公共/非本机地址、LAN 不接受旧共享令牌、管理路由不对 LAN 开放。
- 非法、过期、重放二维码；并发兑换；响应丢失恢复；凭据持久化失败；到期与撤销立即失效；限流。
- 真正的 TLS 连接测试：正确指纹成功，错误指纹/过期证书/目标地址不匹配失败；失败前不发送秘密或照片；禁止重定向和降级。
- Swift 连接检查成功、失败、超时、取消、失效、迟到响应；检查不上传、不调用模型；未就绪禁上传且有操作入口。
- 配对变化、旧配置兼容、任务服务归属、上传同意和幂等恢复；不丢失既有本机学习数据。
- 日志/错误信息不泄露凭据，真实照片和配对产物不进入版本控制。
- `npm run verify`、Swift 测试、相关原生 UI 回归以及真机目标构建。

合成响应只验证连接与客户端流程，不能算作真实模型识别通过。

### 用户真机

1. 更新已安装应用，不删除应用、不重置数据；签名沿用现有个人开发账户，不把测试私有照片打进安装包。
2. 同一 Wi‑Fi 下完成 Mac 二维码 → iPhone 扫码 → 用户确认 → 当前连接检查通过。系统授权由用户在手机上完成。
3. 用户在手机明确选择并同意上传一张真实照片。记录手机提交对应的任务 ID，核对 Mac 收到的图片及手机最终显示的真实返回或明确失败；不能用离线脚本提交替代。
4. 本轮“真实上传与返回”通过要求实际获得真实模型返回；超时或模型失败保留证据，不能把“错误显示正确”当作该项通过。模型内容质量与人工确认仍单独验收。
5. 检查服务停止后的提示与照片保留、恢复后的重新检查、Mac 撤销后的拒绝访问。仅在确认没有正在进行的用户识别任务时执行受控停止；不取消无关任务。

交付报告分别列出：自动化测试、安装/启动、配对、连接检查、真实上传、真实返回、内容质量。任何一项未完成都明确标注；不以一项通过覆盖另一项。

## 6. 本轮不做

- 不开放公网、购买云服务或更换百炼账号。
- 不扩展为全模型测评，不修改裁图/转写规则或降低人工确认门槛。
- 不要求学生辨认订正作者，不让 AI 代写复盘。
- 不清空任何旧实验、失败记录或用户照片。
- 不把本地签名资料、二维码、手机标识或真实学习材料推送 GitHub。代码完成、验证与审查后再按既有授权推送当前开发分支，不强推。
