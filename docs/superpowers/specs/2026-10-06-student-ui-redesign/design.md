## 1. 组织思路

每次打开 App，首页只回答一个问题：**现在做什么**。首页叫「今天」，是一张从现有数据算出来的短清单——这个周末要做的 5–6 步，按顺序排好，做完的打勾、正在做的那一步高亮，并写明「第几步、一共几步、大约几分钟」；屏幕底部永远有一个按钮，字写的就是下一步要做的事（「拍第一页」「勾第 3 张」「录练习纸的结果」）。这个按钮在每一屏都在同一个位置，每一屏做完都把他交给下一步，不再有走到头的页面。周中打开，它告诉他「现在是在纸上做的时候，周末再来」；下个周末打开，它先让他拍新卷子（让 AI 在后台找题），趁等的时候录上周练习纸的结果。Liquid Glass 是材质，不是答案：系统导航栏、工具栏、弹出页、系统按钮用新 SDK 编译后自动变成玻璃（而且用 Xcode 27 编译时已经关不掉）；我们自己只给一处加玻璃——底部那个「下一步」按钮，它是全 App 最重要的功能元素；题目照片、裁图、题干、卡片一律不用玻璃；iOS 18–25 和「降低透明度」时，同一个按钮退成实色。

## 3. 导航模型与「打开先看到什么」

### 3.1 结构

```
NavigationStack
 └ 今天（TodayView，根）                         底部：下一步按钮（NextStepBar）
    ├ 拍卷子（Capture）           → 系统相机 / 相册；第一次上传前弹「上传前看一下」
    ├ 勾出做错的题（Photos）      → 勾选面板（sheet）
    ├ 这周的错题（Items）         → 题目详情 → 改一下（sheet）
    ├ 选这周要练的题（Choose）
    ├ 说说为什么错（Why，逐题）
    ├ 打印练习纸（Print）         → 系统分享 / 打印
    ├ 录结果（Record，逐题）      → 这次的结果（Results）
    └ 设置（Settings，sheet）     → 连接、开发者选项
```

- 不加标签栏（D1 选项 C 演示了加标签栏的样子，见第 9 节）。学生不需要「逛」，他需要「被带着走」。
- 推入的流程页做完后，用 `NavigationPath` 直接替换成下一步（例如「拍完了，下一步」把「拍卷子」换成「勾出做错的题」），返回键始终回到「今天」，不会层层回退。
- 「这周的错题」「以前的练习」「设置」在「今天」底部的「随时可以看」里，不在主流程里。

### 3.2 周计划（WeekPlan）：首页显示什么由它决定

新增一个纯函数（`Domain/V2/WeekPlan.swift`，可单测），输入全部是现有状态，输出「现在处在一周的哪段」「今天的步骤」「下一步按钮」。

**输入（全部已有）**

| 输入 | 来源 |
|---|---|
| 是否配对、连接状态 | `StudyStore.pairing`、`StudyStore.connectionState` |
| 是否在显示缓存 / 离线 | `LoopStore.isShowingCache`、`LoopStore.weekIssue` |
| 本周（ISO 周）照片与错题、往周待练 | `GET /v2/week` → `V2WeekView.week / photos / items / backlog` |
| 本机照片与识别任务（上传中、找题中、要勾、失败） | `StudyStore.state.importedPhotos / recognitionTasks`，`PhotoPickReminder`、`PhotoFailurePlan` |
| 练习列表与当前练习（周、建包时间、练习纸生成时间、每题是否说过为什么） | `GET /v2/practice`、`/v2/practice/:id` → `V2PracticeSummary.week / generatedAt`，`V2PracticeItem.reflected / status` |
| 录了几道 | `GET /v2/practice/:id/summary` → `answered / total` |
| 做题时间（印在封面上） | `GET /v2/settings` → `practiceSlot` |
| 今天的日期 | 手机时钟（本地日历日） |

**规则（从上往下，命中即停）**

| 顺序 | 条件 | 阶段 | 首页显示 |
|---|---|---|---|
| 0 | 没配对，或连接状态为「授权失效 / 版本不一致」 | 先连上 | 连接页（4.2），不显示步骤 |
| 1 | 最近一份练习**已生成练习纸**、**没录完**，且距生成 ≤ 1 天 | 周末 A · 做完了 | 「这周的事做完了 ✓」卡（4.9） |
| 2 | 同上，距生成 2–4 天 | 周中 | 「现在是在纸上做练习的时候」（4.9），次要入口「已经做完了？现在录」 |
| 3 | 同上，距生成 ≥ 5 天 | 下个周末（周末 B） | 步骤清单，含「录练习纸的结果」 |
| 4 | 其他（没有练习，或最近一份已录完 / 还没生成练习纸） | 周末 A | 步骤清单，不含「录结果」 |

「距生成几天」= `generatedAt` 所在本地日历日到今天的天数。三档阈值（1 / 4 / 5）放在一个常量里，试用后可调。

**步骤与完成判定（周末 A；周末 B 在第 2 位插入「录结果」）**

| 步骤 | 完成判定（全是现有字段） | 进行中 / 等待的说法 |
|---|---|---|
| 拍这周的卷子 | 本 ISO 周 `week.photos` 非空，或本机有本周导入的照片；或本次打开点了「这周没发卷子，跳过」（只在内存里记） | 「已拍 3 张」 |
| 录练习纸的结果（仅周末 B） | `summary.answered >= summary.total` | 「录了 2/6 道」 |
| 勾出做错的题 | 本周照片都不在「上传中 / 找题中 / 要你勾」。没认出来的照片**不挡路**：这一行算完成，但用橙字写「1 张没认出来」，点进去可以重试或移除 | 「AI 正在找题（2 张）」「第 3 张要你勾」；完成：「找到 9 道错题」或「找到 9 道错题 · 1 张没认出来」 |
| 选这周要练的题 | 最近一份练习的 `week == week.week`（本周已建练习） | — |
| 说说为什么错（可跳过） | 当前练习每题 `reflected == true`，或本次打开点了「跳过」（只在内存里记） | 「说了 2/6 道」 |
| 打印练习纸 | 当前练习 `generatedAt != nil` | 「正在准备练习纸」 |

「下一步按钮」= 第一个未完成步骤的动作。如果它在等 AI（找题中），按钮变成不可点的「AI 正在找题…」，同时给一个次要按钮跳到下一件能做的事（周末 B 是「先录结果」）。

### 3.3 为什么用「生成后过了几天」而不用星期几

- 他是住校生，回家的日子不一定是周六（有的学校周五傍晚放学）。按星期几判断需要一个新的设置项；按「练习纸生成后过了几天」不需要任何新数据。
- 服务器的掌握判定本来就按「做题日期 − 练习纸首次生成日期」算（`src/services/attemptService.ts` 128–134 行，早于生成日的作答被拒）。首页的时间判断和掌握规则用的是同一个起点。
- 规则只改变**先后和强调**，从不锁住任何操作：周中也能录结果，周末 B 也能先选新题（服务器在已生成练习纸后允许建下一份，现有 `PracticeCardText.canPickNext` 同理）。

### 3.4 「打开的日子不对」时他看到什么

| 情形 | 首页 | 底部按钮 |
|---|---|---|
| 周末 A 打印完，当天又打开 | 「这周的事做完了 ✓ 把练习纸带回学校，周三晚自习在纸上做。」 | 无主按钮；一行「下次打开：下个周末，录结果」；次要「没打出来？现在打印」 |
| 周中（距生成 2–4 天）打开 | 「现在是在纸上做练习的时候」+ 练习纸内容摘要 + 做题规则 | 无主按钮；次要「已经做完了？现在录结果」「又发了卷子？现在拍」 |
| 下个周末，还没录结果 | 步骤 1 拍卷子 → 2 录结果 → … | 「拍第一页」；没发卷子可以「跳过」，按钮立刻变「录练习纸的结果」 |
| 两周没打开，上一份一直没录 | 同周末 B；「录结果」那一行写「上一份练习纸（10/10）还没录」 | 「录练习纸的结果」；录不了可以「先跳过，下次再录」 |
| 选了题，没生成练习纸就关了 App | 周末 A 清单，停在「说说为什么错」或「打印练习纸」 | 对应动作 |
| 没联网 | 顶部一行「没联网，显示的是 14:20 保存的内容」；清单照常显示 | 需要服务器的动作变灰，按钮下写「连上网再继续」；「这周的错题」仍可看 |
| 连接失效（要重新扫码） | 连接页（4.2） | 「重新扫码」 |

### 3.5 他怎么始终知道在第几步、还剩几步、下一步做什么

1. **一周的节奏条**（「今天」标题下）：`周末 拍卷子·打印 → 周中 在纸上做 → 下个周末 录结果`，当前那段填色。
2. **今天的清单**：每行「序号 / 名称 / 一句说明 / 大约几分钟」，做完的打勾变灰，当前那行描边并写「现在做这个」。清单头写「今天大约 13 分钟，一共 5 步」。
3. **下一步按钮上方的小字**：「第 2 步，共 5 步 · 大约 3 分钟」。在流程页里换成流程内进度：「第 3 道，共 6 道」。
4. **每个流程的结尾**：主按钮写「下一步：选这周要练的题」，点了直接进下一步，不回首页再找。
5. **全部做完**：清单收起，换成「这周的事做完了 ✓」卡，告诉他周中做什么、下次什么时候打开。

分钟数是**估计值**（拍 2、录 3、勾 3、选 1、说 5、打印 2），写在一个常量表里，试用后按真实耗时校准。按这个估计，周末 A 约 13 分钟；周末 B（录上周 + 开始这周）约 16 分钟，**超过 15 分钟的目标**，超出的正好是可跳过的「说说为什么错」（跳过后约 11 分钟）。所以这一步的「跳过」按钮必须一直在，D3 的两个选项都保证这一点。

## 4. 逐屏规格

格式：**目的 / 唯一主操作 / 次要操作 / 文案**。文案即最终中文，引号内原样使用。

### 4.0 通用部件

**下一步按钮（NextStepBar）**：固定在底部安全区上方；上面一行小字（进度与时间），下面一个大按钮（图标 + 动词短语）；需要时左边一个次要按钮（「跳过」之类）。三种状态：

| 状态 | 按钮 | 小字 |
|---|---|---|
| 可做 | 「拍第一页」 | 「第 1 步，共 5 步 · 大约 3 分钟」 |
| 等待 | 「AI 正在找题…」（不可点，带转圈） | 「大约 1–2 分钟。可以先做下一步」 |
| 被挡 | 原文字，变灰 | 「没联网，连上后再继续」/「服务器有点忙，过一会儿再试」 |

**状态颜色**沿用现有五色（`Theme.swift` `CardTone`）：灰 = 还在手机上 / 没更新；蓝 = AI 在干活；橙 = 要你处理；绿 = 好了；红 = 出错可重试。永远「图标 + 文字 + 颜色」三样一起，不只靠颜色。

**错误句式**：先说发生了什么，再说东西还在不在，最后给一个按钮。例：「没传上去。照片还在手机里。」〔再试一次〕。服务器原文放进「具体原因」折叠行，不直接当标题。

**全局提示框标题**：现在的「请再试一次」（`SuperErrorLogApp.swift` 63 行）改为「没成功」，按钮「知道了」。

### 4.1 今天（首页）

- 目的：告诉他现在处在一周的哪段、今天要做哪几步、下一步是什么。
- 唯一主操作：底部下一步按钮。
- 次要：点清单任意一行直接去那一步（做完的也能点回去看）；「随时可以看」：这周的错题、以前的练习；右上「设置」（写字，不只是齿轮）。

| 位置 | 文案 |
|---|---|
| 大标题 | 「今天」 |
| 节奏条 | 「周末 拍卷子·打印」「周中 在纸上做」「下个周末 录结果」 |
| 清单头 | 「今天大约 13 分钟，一共 5 步」（周末 B：「今天大约 16 分钟，一共 6 步」） |
| 步骤 1 | 「拍这周的卷子」·「整页拍，一页一张」·「约 2 分钟」；完成：「已拍 3 张」 |
| 步骤（周末 B）| 「录练习纸的结果」·「AI 找题要几分钟，正好先录这个」·「约 3 分钟」；完成：「录完了，6 道里独立做对 4 道」 |
| 步骤 2 | 「勾出做错的题」·「有红叉的题 AI 自己找；没批改的页要你勾」·「约 3 分钟」 |
| 步骤 3 | 「选这周要练的题」·「AI 先帮你选好，5–8 道」·「约 1 分钟」；完成：「选了 6 道」 |
| 步骤 4 | 「说说为什么错」+ 小标签「可跳过」·「每道 AI 问你一句，说一句就行」·「约 5 分钟」；完成：「说了 5/6 道」 |
| 步骤 5 | 「打印练习纸」·「打出来，带回学校」·「约 2 分钟」；完成：「练习纸已生成」（**不说「已打印」**） |
| 当前行角标 | 「现在做这个」 |
| 随时可以看 | 「这周的错题（9）›」「以前的练习 ›」 |
| 空：第一次用、什么都没有 | 清单照常，步骤 1 高亮；没有空白页 |

### 4.2 连接（第一次打开 / 连接失效）

- 目的：让一个人在家的学生知道这一步要谁帮、怎么做。

### 4.7 说说为什么错（原「复盘」）

- 目的：每道题让他自己说出一句「哪里想错了」，并记下他现在的把握，回头和结果对照。AI 只问、只建议，**提交必须由他点**（领域规则不变）。
- 唯一主操作：问答屏「说完了」；确认屏「提交，下一道」（最后一道「提交」）。
- 次要：「这道跳过」；整步跳过「跳过，直接打印」（只在本次打开内记住，不写服务器）。

**开头一屏**（每次进入这步时）：标题「说说为什么错」；「每道题 AI 问你一句，你说一句就行。说出来，下次更容易发现自己是哪里想错了。」；「不想说可以跳过，不影响打印。」；进度「第 1 道，共 6 道」。

**问答屏**：裁图；气泡「AI 问你」+ 问题（服务器生成）；输入框「按住说话，或者打字」；字数「还能写 280 字」；主按钮「说完了」；次要「不回答，直接选」（原「跳过追问，直接选」）；等待「AI 在看你的回答…」。

**确认屏**——现在是 1 个输入框 + 6 + 7 + 4 共 17 个大行；改为一屏三组小按钮：

| 组 | 标题 | 选项（显示 → 提交原文） | 预选 |
|---|---|---|---|
| 一句话 | 「一句话总结（AI 先写了，可以改）」 | 文本框，≤ 60 字；空着也能提交 | AI 写的，角标「AI 写的」 |
| 当时 | 「当时怎么了？」 | 完全不会 → `完全不会`；知道考啥，没想到方法 → `知道考什么但没想到方法`；方法对，步骤错了 → `方法基本正确但步骤出错`；本来会，粗心了 → `本来会但审题计算书写失误`；时间不够 → `时间不足`；其他 → `其他` | AI 猜的，角标「AI 猜的」 |
| 错在哪 | 「主要错在哪？」 | 概念没弄懂 → `知识概念`；方法选错了 → `方法选择`；推理中间断了 → `推理步骤`；算错了 → `计算`；题目没看全 → `审题遗漏`；写法不规范 → `表达规范`；时间不够或走神 → `时间注意力状态` | AI 猜的 |
| 把握 | 「现在再做这道题，有把握吗？」 | 还是不会 → 0；看提示可能会 → 1；现在做应该会 → 2；过几天也会 → 3 | **从不预选**；小字「这个要你自己选，AI 不帮你猜」 |

- 有上次的记录时角标写「你上次选的」（原「上次的选择」）。
- 缺项时按钮变灰，按钮上方一行：「还差：有没有把握」（原 `missingHints`，改成大白话）。
- 显示文字只是**别名**：`V2ReflectionText` 的原文常量与 `ReflectionForm` 的提交值不动（`V2Enums.swift` 325 行注释「必须原样发回」），新增一张别名表做显示。
- 全部说完：「说完了 ✓ 6 道里说了 5 道」→ 主按钮「下一步：打印练习纸」。

### 4.8 打印练习纸

- 目的：把练习纸打出来。**手机不知道他到底打没打印**——服务器的 `generatedAt` 只表示「打印内容已准备好」（`src/v2/printService.ts` 309–314 行）。所以不替他说「已打印」，由他自己说。
- 唯一主操作：准备中无（可离开）；就绪后「打印」；从打印/分享回来后变成「打印好了，回到今天」。
- 次要：「打印前看一眼这 2 道」各行；回来后「再打印」；失败时「再试一次」。

| 状态 | 文案 |
|---|---|
| 准备中 | 「正在准备练习纸… 第 3/6 道」「大约 1 分钟。可以先离开，回来接着准备。」 |
| 排版中 | 「正在排版…」 |
| 就绪 | 练习纸预览（A4，封面 + 题目页 + 可撕答案页）；按钮「打印」（系统分享面板，里面有「打印」） |
| 看一眼 | 标题「打印前看一眼这 2 道」；每行服务器给的原因（`glanceReason`），点开看图 |
| 回来后 | 主按钮「打印好了，回到今天」；小字「打印机没反应？可以再点一次『打印』，或者用『存储到文件』发给家里人打印。」 |
| 准备失败 | 「练习纸没准备好：{服务器原文}」〔再试一次〕 |
| 超时 | 「准备得太久了，再试一次。」〔再试一次〕 |
| 排版失败 | 「练习纸排版没成功，再试一次。」〔再试一次〕 |
| 图片没下全 | 「有几张图没下载下来，再试一次。」〔再试一次〕 |

「打印好了」不写服务器、不落盘，只是把他带回「今天」（显示「这周的事做完了」）。首页任何地方都只说「练习纸已生成」。

### 4.9 这周的事做完了 / 周中

这两种都是「今天」的状态，不是单独的页。

**做完了**（距生成 ≤ 1 天）

> 「做的时候：不看答案，独立做；卡住先看一级提示，再看二级；做完打勾，写上做题日期。」（与练习纸封面的三条规则同一说法，`printService.ts` 55 行）
> 「下个周末打开 App，录一下做的结果。」
> 底部：一行「下次打开：下个周末，录结果」；次要「没打出来？现在打印」（因为手机不知道他是否真的打印了，见 4.8，这个入口一直留着）

**周中**（距生成 2–4 天）

### 4.10 录结果

- 目的：把纸上每道题怎么做的、对不对、哪天做的告诉服务器。
- 唯一主操作：日期屏「下一步」；每题「下一道」；最后「提交 6 道结果」。
- 次要：「这道不是这天做的？改日期」；「上一道」；日期屏「先跳过，下次再录」。

**日期屏**：「练习纸是哪天做的？」；最近 7 天的按钮（「周三 10/14」…「今天」），**不预选**（现在默认「今天」，但他通常周六录、周三做，默认值多半是错的）；小字「当天做对不算真会，隔 3 天以上独立做对才算，所以日期要填准。」；「不是同一天做的？后面每道可以单独改。」

**每题屏**（D4-A）：「第 2 道，共 6 道」/ 裁图 / 题干前两行 / 「这道你是怎么做的？」五个大按钮——「独立做出」「看了一级提示」「看了二级提示」「没做出来」「没做」（与练习纸上的勾选框同一说法，`printService.ts` 56 行）/ 选了前三个后出现「做对了吗？对照练习纸最后一页的答案」〔对了〕〔错了〕/ 选「没做出来」后出现「卡在哪一步？（可以不填）」。

**提交**：一次提交全部（服务器逐条判定）。被拒的题回到对应那一屏，上面一行红字：「这道没提交上：{服务器原文}」。重新进入时，已录过的题（练习详情里该题 `status` 已离开 `packet_generated`）不再出现，第一屏写「已录 3 道，还剩 3 道」（判定方法需实现时核对，见 11.3）。

### 4.11 这次的结果（原「练习回报」）

- 目的：告诉他这周几道真会了、几道下次再来、他的感觉准不准；然后把他交给下一步。
- 唯一主操作：周末 B 流程里「下一步：勾出做错的题」（或当时的下一步）；从「以前的练习」进入时「回到今天」。

## 7. Liquid Glass：用在哪，不用在哪

### 7.1 结论（检验「玻璃是材质，问题是引导」这一判断）

同意，补一处。**同意**：学生卡住的 11 个点没有一个是材质能解决的——它们是「不知道下一步」「说法不对」「走到头没出口」；Apple 自己的设计规范也说玻璃属于「功能层」，**不要用在内容层**（见 7.8）。**补充**：用 Xcode 27（iOS 27 SDK）编译时，系统控件的玻璃外观**已经关不掉**——`UIDesignRequiresCompatibility` 这个兼容开关在为 iOS 27 及以后编译时被系统忽略（7.8）。所以问题不是「要不要玻璃」，而是「系统部分已经是玻璃了，我们自己画的扁平按钮和底栏要和它协调」。这也是把所有主操作收进一个统一的 `NextStepBar` 的另一个理由：只有一处自定义，就只有一处需要做两套外观。

原型里「D5 玻璃用量」的选项 C 把卡片也做成玻璃，可以直接在手机上看到为什么不推荐：题目照片上压一层半透明标签，题干对比度下降。

### 7.2 免费得到的（不写代码，iOS 26 及以上自动生效）

| 我们用到的系统部件 | iOS 26+ 上的样子 |
|---|---|
| `NavigationStack` 导航栏、返回键、工具栏按钮（设置、保存、取消、看原图） | 浮在内容上的玻璃按钮；滚动时内容在栏下淡出（scroll edge effect） |
| `.sheet`（勾选面板、改一下、上传前看一下、设置） | 圆角更大，半高时离屏幕边缘有间距 |
| `.confirmationDialog`、`.alert` | 新外观 |
| `Picker(.segmented)`、`Toggle`、`DatePicker`、`TextField` | 新外观 |
| 系统分享面板、`PhotosPicker`、系统相机 | 系统自己的样子 |
| `.buttonStyle(.borderedProminent)` / `.bordered` | 新外观（但不是玻璃） |

不受影响、保持扁平的：`PrimaryButton`、`PaperCard`、`ChoiceRow`、自己画背景的底栏（现在的 `safeAreaInset` + `Palette.card`）。这些是第 10 节要统一的。

### 7.3 自定义玻璃：只有一处——底部下一步按钮

```swift
/// 每屏唯一主操作，固定在底部。iOS 26+ 用 Liquid Glass；iOS 18–25 或「降低透明度」时用实色。
struct NextStepBar: View {
  let model: NextStepModel          // title, systemImage, caption, isEnabled, secondary
  let action: () -> Void
  @Environment(\.accessibilityReduceTransparency) private var reduceTransparency

  var body: some View {
    VStack(spacing: 6) {
      Text(model.caption).font(.footnote).foregroundStyle(.secondary)   // 第 2 步，共 5 步 · 大约 3 分钟
      buttons
    }
    .padding(.horizontal, 16).padding(.top, 8)
    .accessibilityElement(children: .contain)
    .accessibilityIdentifier("next-step-bar")
  }

  @ViewBuilder private var buttons: some View {
    if #available(iOS 26.0, *), !reduceTransparency {
      GlassEffectContainer(spacing: 10) {
        HStack(spacing: 10) {
          if let secondary = model.secondary {
            Button(secondary.title, action: secondary.action).buttonStyle(.glass)
          }
          Button(action: action) {
            Label(model.title, systemImage: model.systemImage).frame(maxWidth: .infinity, minHeight: 34)
          }
          .buttonStyle(.glassProminent)
          .tint(Palette.teal)
          .disabled(!model.isEnabled)
        }
      }
    } else {
      HStack(spacing: 10) {
        if let secondary = model.secondary {
          Button(secondary.title, action: secondary.action).buttonStyle(.bordered)
        }
        Button(action: action) { Label(model.title, systemImage: model.systemImage) }
          .buttonStyle(PrimaryButton())
          .disabled(!model.isEnabled)
      }
    }
  }
}

extension View {
  /// iOS 26+ 用 safeAreaBar：滚动内容的边缘效果会延伸到这条自定义栏下面；更早系统用 safeAreaInset + .bar 材质。
  @ViewBuilder func nextStepBar(_ model: NextStepModel?, action: @escaping () -> Void) -> some View {
    if #available(iOS 26.0, *) {
      safeAreaBar(edge: .bottom) { if let model { NextStepBar(model: model, action: action) } }
    } else {
      safeAreaInset(edge: .bottom, spacing: 0) {
        if let model { NextStepBar(model: model, action: action).padding(.bottom, 8).background(.bar) }
      }
    }
  }
}
```

- 为什么只给它：它是每一屏唯一的主操作，是 HIG 说的「最重要的功能元素」；它浮在内容上面，正是玻璃该在的「功能层」。
- `GlassEffectContainer` 让主次两个按钮在出现/消失（例如「跳过」只在某些步骤出现）时作为一组玻璃渲染、互相融合；需要动画时再加 `glassEffectID(_:in:)`。第 1 期不需要。
- 「降低透明度」打开时我们主动退成实色。文档只说系统组件会自动适配、自定义元素「要测试」，没有写 `.glassEffect` / `.glassProminent` 在这个设置下具体变成什么样（7.8 未核实项），所以保守处理。
- `.tint(Palette.teal)` 对 `.glassProminent` 生效：文档说它「类似 `borderedProminent`」，后者用 tint 着色。需要在 iOS 26.3 模拟器上确认（本机已装 iOS 26.3 与 18.6 两个模拟器运行时）。

### 7.4 不用玻璃的地方

| 元素 | 为什么 |
|---|---|
| 卷子照片、题目裁图、练习纸预览 | 内容层；任何半透明叠层都会降低笔迹和数字的可读性 |
| 题干、AI 的问题、他的回答 | 大段文字，HIG：大量文字用 regular 变体，且这些是内容不是控件 |
| 今天的清单、错题卡、结果分组 | 内容层；当前步骤用实色描边高亮即可 |
| 状态标签（找好了 / 要你勾…） | 靠颜色 + 文字区分，玻璃会冲淡颜色 |
| 节奏条 | 内容层，实色 |
| 不加标签栏 | 见 D1；如果选了标签栏，系统 `TabView` 自动是玻璃，下一步按钮改放 `tabViewBottomAccessory`（iOS 26+） |

### 7.5 iOS 18–25 的样子

- 系统部件：iOS 18 的原样（不透明导航栏、贴边 sheet、标签栏）。
- 下一步按钮：`safeAreaInset` + `.bar` 材质底（iOS 15 起就有的模糊材质）+ 实色青绿按钮（现有 `PrimaryButton`）。
- 布局、文案、步骤、按钮位置**完全一样**。引导不依赖玻璃，所以学生的系统版本未知不构成风险。
- iPhone 13 能装 iOS 26（Apple 的 iOS 26 兼容机型名单包含 iPhone 13），所以两种样子他都可能看到；原型右上「系统版本」可切换对照。

### 7.6 无障碍

- 「降低透明度」：自定义按钮退实色（上面已写）；系统部件自动适配。
- 「增强对比度」：状态色用现有 `CardTone` 深浅两套，图标 + 文字不依赖颜色。
- 动态字体：底部按钮文字最多两行、按钮高度随字体变；清单行在最大字号下纵向排列。
- VoiceOver：清单每行读作「第 2 步，勾出做错的题，现在做这个，按钮」；底部按钮读作「下一步：勾第 3 张，第 2 步，共 5 步」。
- 减少动态效果：不用自动翻页动画；做完一步的打勾只变色不位移。

### 7.7 图标

- 步骤图标用 SF Symbols（`camera`、`checklist`、`list.bullet.rectangle`、`bubble.left`、`printer`、`square.and.pencil`），系统版本自带，与玻璃风格一致，零成本。
- App 图标的 iOS 26 分层玻璃图标（Icon Composer 制作）与引导无关，不在本次范围；本稿未核实其工具链细节。

### 7.8 已核实 / 未核实

**已核实**（2026-10-06）：

1. 本机 iOS 27 SDK 的 SwiftUI 接口文件（`/Applications/Xcode.app/…/iPhoneOS27.0.sdk/System/Library/Frameworks/SwiftUI.framework/Modules/SwiftUI.swiftmodule/arm64e-apple-ios.swiftinterface` 与 `SwiftUICore` 同名文件）中的声明与可用性：
   - `glassEffect(_ glass: Glass = .regular, in shape: some Shape = DefaultGlassEffectShape())`：iOS 26.0+
   - `struct Glass`：`regular`、`clear`、`identity`、`tint(_:)`、`interactive(_:)`；iOS 26.0+
   - `GlassEffectContainer(spacing:content:)`、`glassEffectID(_:in:)`：iOS 26.0+
   - `PrimitiveButtonStyle.glass`、`.glassProminent`：iOS 26.0+
   - `safeAreaBar(edge: VerticalEdge, …)` 与 `safeAreaBar(edge: HorizontalEdge, …)`：iOS 26.0+
   - `tabBarMinimizeBehavior(_:)`、`tabViewBottomAccessory(content:)`、`ToolbarSpacer`、`scrollEdgeEffectStyle(_:for:)`、`backgroundExtensionEffect()`：iOS 26.0+
   - SDK 里没有找到 iOS 27 新增的玻璃 API；本设计只用 iOS 26 的。
2. Apple 开发者文档：
   - [glassEffect(_:in:)](https://developer.apple.com/documentation/swiftui/view/glasseffect(_:in:))——默认 regular + 胶囊形，常与 `GlassEffectContainer` 合用。
   - [GlassEffectContainer](https://developer.apple.com/documentation/swiftui/glasseffectcontainer)、[Glass](https://developer.apple.com/documentation/swiftui/glass)、[glassProminent](https://developer.apple.com/documentation/swiftui/primitivebuttonstyle/glassprominent)（「类似 borderedProminent」）、[glass](https://developer.apple.com/documentation/swiftui/primitivebuttonstyle/glass)、[glassEffectID(_:in:)](https://developer.apple.com/documentation/swiftui/view/glasseffectid(_:in:))。
   - [safeAreaBar](https://developer.apple.com/documentation/swiftui/view/safeareabar(edge:alignment:spacing:content:))——与 `safeAreaInset` 相同，另外把滚动视图的边缘效果延伸到这条栏下。
   - [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)——标准的栏、sheet、popover、控件自动采用玻璃；自定义控件上「少用」，「只用在最重要的功能元素上」；减少控件和导航元素上的自定义背景；用多种显示与无障碍设置测试自定义元素。
   - [HIG · Materials](https://developer.apple.com/design/human-interface-guidelines/materials)——玻璃构成浮在内容层之上的功能层；「Don't use Liquid Glass in the content layer」；clear 变体只用在照片、视频这类丰富背景之上，必要时加 35% 暗层。
   - [UIDesignRequiresCompatibility](https://developer.apple.com/documentation/bundleresources/information-property-list/uidesignrequirescompatibility)——设为 YES 时以旧 SDK 外观运行；**为 iOS 27 及以后编译时系统忽略此键**。
   - [accessibilityReduceTransparency](https://developer.apple.com/documentation/swiftui/environmentvalues/accessibilityreducetransparency)——iOS 13.0+。
3. [Apple 支持：与 iOS 26 兼容的 iPhone 机型](https://support.apple.com/en-om/guide/iphone/iphe3fa5df43/ios)——包含 iPhone 13。
4. 本机模拟器运行时：iOS 18.6、iOS 26.3（`xcrun simctl list runtimes`）；没有 iOS 27 模拟器运行时。

**未核实**：

1. `.glassEffect` / `.glassProminent` 在「降低透明度」「增强对比度」下的具体外观（文档只说要测试）——方案保守退实色，实现期在模拟器上看。
2. `.tint(_:)` 对 `.glassProminent` 的着色效果与对比度（文档只说类似 `borderedProminent`）。
3. iOS 27 系统上的玻璃外观相对 iOS 26 是否有变化（本机无 iOS 27 运行时，Xcode 27 也只装了 26.3 / 18.6 运行时）。
4. 学生手机的实际 iOS 版本（未知，设计对两种都成立）。
5. Icon Composer 分层图标（不在本次范围）。

## 11. 开放问题（现有接口和状态给不了的）

1. **他到底打没打印。** 服务器只知道打印内容准备好了（`generatedAt`）。本设计因此只说「练习纸已生成」，「打印好了」只是导航。若想在首页如实显示「已打印」，需要一个新状态：要么本机按练习记一个标记（可从 `UIActivityViewController` 的完成回调读到是否选了「打印」），要么服务器加字段。**本设计没有用它。**
2. **「跳过」不保存。** 「这周没发卷子，跳过」「说说为什么错，跳过」只在本次打开内有效；关掉 App 再开会再问一次。若要记住，需要本机新字段。
3. **重新进入录结果时哪些题已录。** 现有 `ReturnForm` 每次都从全部题开始（`ReturnForm.swift` 36–38 行），已录的题再交会被服务器拒（「该题在此复习包中已回传」）。设计里用「练习详情里该题状态已离开 `packet_generated`」判断已录；需要实现时核对确认轮（`temporarily_mastered` 再练）的题是否也成立。若不可靠，需要服务器在练习详情里给每题一个 `recorded`。
4. **一周的节奏只按「生成后几天」估计。** 如果他实际是周五回家、或者某周没回家，阈值会偏。若要按他的实际作息，需要一个新的设置项（例如「通常哪天回家」）。
5. **连拍多页。** 系统相机一次一张；`VisionKit` 的文档扫描可以连拍，但会自动裁边和拉正，可能违反「整页拍全，别裁边」并影响识别。没有放进设计。
6. **连接只能靠大人。** 重新配对需要管理端生成二维码，没有学生自助恢复的接口。设计只是把这件事说清楚。
7. **练习纸上的「一级提示 / 二级提示」。** 这是服务器写死的打印文案（`printService.ts` 55–56 行）；App 跟着纸用同一说法。想改成「提示 1 / 提示 2」需要改服务器。
8. **分钟数。** 清单上的「约 N 分钟」是估计，没有测量。试用时可以在本机记录每步耗时（新的本地数据，需同意）后校准。
9. **服务器的少数原文仍偏书面。** 选题说明（`notes`，如「候选知识点较集中，为满足最低题量…」）、修改面板的拒绝原因原样显示；要彻底口语化需要改服务器文案。
