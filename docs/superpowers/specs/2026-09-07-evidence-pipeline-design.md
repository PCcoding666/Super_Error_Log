# 真实错题证据链与百炼分阶段评测

## 已确认的产品目标

依据 2026-09-07 用户确认的完整证据链：纸质材料 → 完整题目和关键图示 → 原始作答、订正、批注 → 有证据的 AI 诊断 → 学生确认 → 干净纸质复习 → 真实结果回传。不能把 OCR 或合成测试通过宣称为真实学习效果。

## 架构选择

保留现有 TypeScript / Express / React SSR / SQLite 应用，新增可版本化的证据记录。比较三个方案：单次模型输出全部（成本低但不可定位错误）、每字段独立模型（调用多且易失去上下文）、分阶段模型（采用）。阶段为 layout、transcribe、diagnose、coach、match；实际裁图、选题排序和状态计算由确定性代码完成。

- layout：整页识别题号和题目范围，保留共享题干，标记可见批改证据，不能把整页所有题自动宣布为错题。
- transcribe：针对一个范围，输出完整题干、图示坐标、学生作答步骤、教师批注、订正、可见参考答案；所有区域关联同一归一化来源图片。看不清返回不确定性，不能补造学生答案。
- diagnose：只基于已校对的题目与作答证据，返回候选错因、证据 ID、具体错误说明和一个澄清问题；不能写入学生反思。
- coach：基于校对内容和诊断生成分级提示与参考解法；生成答案始终标记 AI 参考，独立于照片中的参考答案。
- match：识别回传页短 ID；识别结果不能自动成为正确或掌握事实。

每个阶段可配置百炼模型。通用 OpenAI 兼容模式保留；百炼模式强制其 HTTPS 官方域名，禁止向未知网关传送题目。真实模式缺配置时失败，不能降级 Mock。显式演示模式继续支持合成测试。

## 数据与 UI

新增独立 evidence_record 表保存版本化 JSON、提取模型、人工校对标记、诊断和提示版本。已有 error_item 与复习流程继续使用。所有真实题必须校对后进入反思；编辑题干/作答/图示时清除旧诊断、提示和校对状态。已进入复习包的内容不可原地修改，避免纸面与库内容漂移。

证据页面展示原图、分区图与可编辑全文，附坐标和置信度；学生原始作答、教师批注、参考答案、未知归属必须分开。确认时检查完整题干与所有必要图示，打印只使用已确认题干与已确认干净图示；不能使用整张带答案原图。

## 首轮评测

只在用户提供的 13 张照片中选取 10 道真实题，覆盖图示、多问、手写和批注交叠。人工核对真值；无法判定心理错因的题使用“应澄清/不应断言”为真值。先固定输入分别评测每阶段，再运行候选组合 E2E。模型自评不作为准确率。

候选来源为百炼官方当前模型目录，保留来源 URL 和核验日期。按账号地域和可调用模型选择 2–4 个候选，记录失败率、关键字段正确率、图框 IoU/包含完整性、作答归属错误、无证据断言、提示泄漏、token、耗时和估算费用。阶段赢家仅对本样本、本配置成立；并列保留，不夸大全局最优。

真实请求必须有地域、密钥和明确的调用/费用上限。没有真值、调用记录或人工判定时，报告状态为未评测，不生成赢家。费用是基于官方单价和 usage 的估算，不冒充账单。

## Global Constraints

- 保留用户已有未提交修改；不 commit、push、部署或删除旧数据。
- 原始 HEIC 只读；转换、裁图、真值和实测输出存放 git-ignored 本地目录。
- 密钥只从本机配置读取，不能进入日志、报告、浏览器或 Git。
- AI 建议、学生确认、真实重做结果三者分离；禁止伪造学生输入。
- 原图和私人反思仍受学生权限保护。
- 10 道技术验收不等于完成延迟学习验证。

## 验收

自动测试覆盖坐标/JSON 校验、HEIC 转换、缺配置拒绝、模型阶段路由、证据持久化和校对失效、无原答案打印、实际日期与重印时钟、错误后重排、家长权限、评测预算和缺失结果处理。真实验收逐题保存可追踪材料和检查项；未获得 API Key 或学生确认的步骤明确暂停在对应状态。
