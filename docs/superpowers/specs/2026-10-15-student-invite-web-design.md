# 手机网页版与学生邀请码设计（2026-10-15）

## 授权与交付
用户已同意沿用现有服务器做手机版网页、每个学生一个邀请码；WorkBuddy 实现，Codex review/验收，上线后在 PC iPhone 打开并添加主屏幕。无需再次讨论已同意的方案。网页是手机主操作面，更新 2026-09-29 设计中 Web 仅看板的限制。

## 已核实基线
基于提交 5436a44（线上 0.4.0-r1 对应发布分支），不要从落后 62 次提交的主目录开发。已有 /s/ SSR 手机全流程、manifest、service worker、录音上传及 Qwen ASR 3.1。线上 /s/ HTTP 200。已有 getDb/config 等进程全局单例和唯一学生档案，现有多个设备码不等于多个学生。不得把不同学生接进共用档案。

## 学生体验
打开 https://study.pccoding666.com/s/ → 输入 12 位专属邀请码 → 自己的首页 → 添加到主屏幕（可稍后） → 拍照/选相册 → 勾错题 → AI追问与修正 → 打印/保存练习 → 纸上重做 → 回传结果。
邀请码由管理员生成，一次性，7天过期，大小写不敏感，允许空格/短横线分组。登录保存30天。换手机或清理浏览器由管理员给同一学生补码，保留学习记录。退出登录立即使该会话失效并清掉本机页面标记；不删除学习数据。错误提示不暴露学生存在性。

## 隔离方案与规模边界
本轮面向受控试用，最多3个学生空间（含验收空间）。采用独立数据目录和独立 Node 子进程复用已验证的单学生服务。这样异步识别、打印、全局数据库及 AI provider 缓存均不会串学生。主进程 /s/ 入口负责邀请码、登录会话及转发；/v1 /v2 保持旧 App 原有数据，不向新学生导入旧测试题。管理员存储在 SEL_STUDENT_HOST_DIR（默认旧 dataDir/student-host），各空间在 students/<server-generated-uuid>，目录0700。实例数达到上限必须拒绝新建，不能偷用其他人的空间。后续超过试用规模另行评估多租户数据库，当前不宣称可大规模分发。
子进程仅监听回环随机端口，父进程管理生命周期；每个学生最多一个进程，启动并发去重，启动超时20秒，崩溃不能错误路由到别人。重启后恢复已创建学生的工作。退出父进程/IPC断开停止子进程，避免孤儿。通过环境变量在加载 config 前设置独立 SEL_DATA_DIR 和 SEL_MOBILE_DATA_DIR。不要在共享进程请求间切换 process.env 或全局 db。

## 鉴权与转发
registry SQLite 用事务存 students/invitations/sessions；只存邀请码和会话令牌 SHA256，邀请码安全随机60bit以上，会话随机256bit。邀请码只能并发兑换成功一次。管理员CLI create / invite <studentId> / list / revoke-sessions <studentId>；没有公网管理页。SQLite忙处理有限超时；目录及数据库权限私有。
前台会话 sel_student：HttpOnly、Secure（仅loopback测试可免）、SameSite=Lax、Path=/s。服务端凭哈希会话决定学生，客户端不得指定目录/端口/studentId；过期、撤销和缺失会话只能看到登录。POST校验同源（Origin/null/cross-site拒绝），失败登录按真实IP限速，10分钟最多10次，不能信任直连伪造X-Real-IP。
隔离worker复用 PairingManager 生成仅父进程知道的内部设备令牌，父进程经IPC获得端口/令牌，向worker注入 sel_device；过滤用户携带的sel_device、认证头和转发头，绝不把内部令牌Set-Cookie给浏览器。内部令牌刷新需确保长期运行仍能使用。gateway 禁止旧 /s/pair 绕过新登录、禁止路径规范化或编码穿越到 /v1 /v2，只接受 /s/ 相对路径。请求体流式转发，不先解析上传multipart；有限响应/连接超时，断连取消请求。保留业务Cookie、原始Host、正确真实IP（父进程可信Caddy规则），Set-Cookie仅允许既有业务cookie，不能覆盖sel_student。
公共资源仅脚本/样式/icon/manifest/sw/offline；所有含学生数据HTML/图片/打印响应no-store。service worker只缓存静态壳，退出后不能看到上一学生内容。不同学生猜到同一题目/练习/job/media ID也只访问自己的worker数据。

## ASR与打印
保留 qwen-audio-3.1-asr-flash（官方2026-10-15模型目录已核实 https://help.aliyun.com/zh/model-studio/model-list-speech-recognition/ ），不使用浏览器 SpeechRecognition 作为云转写替代。北京百炼原生接口，沿用现有30秒/大小限制及M4A/WebM支持；仅内存处理，音频/转写/密钥不入日志。明确提示录音发送至百炼处理，失败保留原输入、可重试或键盘输入、绝不自动提交反思。实测Safari录音容器与服务器接口；不宣称离线语音。
打印复用现有 /s/ 原生浏览器打印页面，学生可分享/存PDF；验证题目页不泄露答案、提示与答案分开。不把Swift排版直接移植。

## 发布与手机
功能flag SEL_STUDENT_HOST_ENABLED=1 才替换 /s；默认关闭保留基线。旧数据库和照片保持原状。新版入口以及部署说明都用域名HTTPS（IP自签不能作为浏览器录音发布入口）。部署前备份，确认无识别任务在处理，校验发布包，有限重启；失败回到0.4.0-r1。用户已授权本次交付上线和手机使用。无需push GitHub。
手机先打开登录/安装页；添加主屏幕需要Safari分享菜单的真实确认。若工具不能点击手机，必须说明仅缺哪一步，不能把打开网页称为安装成功。不安装新的原生App。

## 验收
A/B学生会话隔离：不同设置和记录，复制图片/题目/练习URL不得读到对方；失败码、重复码、过期、撤销、重启、worker崩溃均覆盖。复用既有浏览器全流程用例，新增登录+两学生串行/并发+退出离线测试。真实模型用合成录音和试验空间；不能把用户测试数据迁给学生。检查后台恢复和3学生上限、内存；发布后匿名登录页、旧App API和两学生设置隔离实测。手机真机录音、拍照、主屏幕和实际打印分别标注通过或未验证。
