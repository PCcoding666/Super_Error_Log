# 管理后台：邀请码账号用量与调用性能

用户目标：管理员查看所有邀请码对应账号的使用情况，重点是输入/输出 tokens、调用耗时、成功率和失败原因。2026-10-20 用户明确选择用量与速度，不包含识别准确率评测。

## 交付

在现有 Express/React SSR 应用内挂载 `/admin/`，沿用无 hydration 的表单页面。独立管理员登录；服务器 CLI 生成/重置管理员密码，重置使已有管理会话失效。学生邀请码和学生 cookie 均不能访问管理数据。只读账号/调用管理页面，不增加删除学生、撤销会话或修改学习记录的网页操作。

页面包括总览、账号列表、邀请码状态、账号使用统计、模型/功能汇总与调用明细。筛选账号、日期、模型和功能，明细分页。账号使用统计为累计照片、错题、练习包、复盘、重做次数及最近活动；AI 指标遵循当前筛选。日期按 Asia/Singapore 的自然日处理，结束日期包含整日。

## 数据与口径

保留每学生独立进程、独立数据库。统一 AI 调用采集写入该学生目录的独立 SQLite；文本、视觉、语音的实际 HTTP 尝试各记一次，重试也分别计数。仅持久化时间、模型、功能、HTTP 状态、输入/输出 tokens、耗时和受控错误分类，不记录请求正文、响应正文、学生文字、音频或密钥。

调用耗时从 HTTP 请求前到响应读取/解析结束，不含排队或后续业务处理；平均值和 P95 仅使用有耗时的调用，标明样本数。接口成功表示 HTTP 请求及客户端响应解析成功，不代表识别内容正确。取消、超时、HTTP 错误、无效 JSON 均可区分。无调用时成功率和耗时为未采集。供应商未返回 usage 时保留 null；可计量输入/输出分别求和，展示已采集条数，不把未知值当 0。

历史视觉 attempts 日志可恢复白名单元数据，缺少耗时保留未知，与新采集记录通过调用 ID 去重；历史记录不包含全部文本/语音调用，界面明确覆盖范围。损坏/不可读的历史文件显示缺失提示。邀请码仅保存哈希，后台提供独立邀请码编号、创建/到期/兑换状态；不还原原码、不展示哈希。同一账号多个邀请码只统计一次账号用量。

## 权限和接入

仅学生 host 主进程挂后台，worker 不提供后台。管理密码只保存 scrypt 派生值；会话仅保存 SHA256，12 小时有效，独立 HttpOnly、SameSite=Strict、HTTPS Secure cookie，Path=/admin。登录限速、POST 同源校验、无缓存、安全响应头。默认无管理员凭据时登录失败，必须由服务器管理员运行初始化命令。

管理汇总只读取注册表列出的学生目录，以只读连接读学习库，不启动 worker，不执行恢复逻辑，不创建/修改学生业务数据。错误提示不包含内部路径或原始异常。

## 验证与交付边界

Node >=24，无新增运行时依赖。测试真实临时 SQLite、合成 HTTP 服务与浏览器，验证成功/失败/取消、缺失 usage、双账号归属、补发邀请码、时间边界、权限、会话失效、筛选和分页。运行 `SEL_AI_MODE=mock npm run verify`。

本次交付代码、使用说明和验证证据；不调用收费模型、不接触生产学生数据。生产部署需按仓库要求获得当次授权。
