## Review Focus

1. 已耗用预算但响应/证据尚未落盘时崩溃，恢复不能得到免费预算。
2. verify 返回合法但检查不通过的结果，与 HTTP 瞬时错误混合时，每阶段实际调用仍有上限。
3. 首次恢复被暂停时立即上传，不能暂时超收；历史超额任务不能被删除。
4. 同一未完成题目的两次恢复扫描重叠，或停止时模型迟到返回，不能开始额外调用。
5. 应用切回旧版本后证书仍可维护，且 Caddy 不能因此获得学生数据权限。

## R1-1：统一持久化调用预算与人工重试轮次（F1/F2/F7）

文件入口：`src/mobile/service.ts`、`vision.ts`、`contracts.ts`、`store.ts`、`tests/integration/mobileRetryBudget.test.ts`、`mobileVision.test.ts`、`mobileRecognition.test.ts`。

接口责任：service/store 拥有工作轮次和预算；vision 每次发 HTTP 前取得准许，不拥有另一套隐式重试循环。阶段至少区分 inventory/transcribe/verify/ground，清单以照片为工作单元，后续以题目为工作单元。

- [ ] 先写 RED：真实适配器 + 合成 HTTP，阶段耗用一至两次后关闭旧实例，从同一数据目录重开，累计请求不超过三次。不能用终态上再扫描代替重启。
- [ ] 先写 RED：verify 内容未通过 → ground → verify 瞬时失败 → 自动恢复的混合路径。即使尚可继续 grounding，同轮同阶段也不能发第四次请求；明确显示预算耗尽，保留证据。
- [ ] 先写 RED：清单耗尽后人工重试、某题耗尽但其他题尚在处理时人工重试，均有明确新轮次、旧记录不被覆盖、已完成阶段不重复。
- [ ] 覆盖预算预约写入失败不发 HTTP；预约成功而结果未落盘即崩溃，重启不会把该次预约免费归还。旧格式有可用调用记录时保守恢复，无法确定时停止自动新增调用并给出可人工恢复状态，不静默清零。
- [ ] 做最小修复；统一每轮每阶段最多三次实际自动调用（首次也计入），成功但检查未通过的请求同样计入。终态不抹掉审计计数，人工重试只为目标工作单元建立新轮次。
- [ ] 运行上述目标文件的测试，核对认证/权限/格式错误不自动循环，EIO 仍为存储故障而非模型失败。记录 RED/GREEN 与持久化前后示例，示例不含私密数据。

## R1-2：启动准入、唯一执行权与关闭生命周期（F3/F4/F6/F8）

文件入口：`src/mobile/service.ts`、`admission.ts`、`router.ts`、`cloudAssembly.ts`、`vision.ts`，以及 `mobileAdmission.test.ts`、`mobileRecovery.test.ts`、预算和装配相关现有测试。

接口责任：启动明确有“容量恢复尚未完成”状态；服务关闭是可等待的识别 worker 收尾，不只是 HTTP 关闭。R1-1 的调用准许也检查停止和存储状态。恢复扫描与普通重试共用工作单元执行权。

- [ ] 先写 RED：预置十个旧任务，用 barrier 暂停首次容量恢复；立即尝试新上传，必须不能创建第十一张。允许尚未监听或明确暂不接收，不能先等 health 满额再测试。恢复完成后旧任务可继续；终态一个才空出一个名额。
- [ ] 覆盖历史超过十张时保留全部旧任务并拒绝新增；容量满时既有查询与幂等重放不应被误拒。
- [ ] 先写 RED：同一未完成题目两次扫描同时越过读状态边界，首次模型响应为瞬时失败；断言只有一个执行者，退避到期前无额外调用，容量只占一份。不能只扫描 completed 任务。
- [ ] 先写 RED：分别挂住 inventory、transcribe、第一题请求，执行 stop 或从另一条路径触发存储故障，再放回响应；不得发起下一阶段或下一题请求。退避 timer 与扫描迟到回调也不能再发模型工作。
- [ ] 做最小修复：新增准入之前完成旧任务容量重建，恢复扫描取得唯一执行权，建立可等待且有明确停止语义的 worker 收尾。不得以完成全部模型请求作为容量初始化的前提。
- [ ] 修复测试生命周期：解除或取消测试 barrier，停止并等待所有 worker、timer、扫描及 HTTP 资源后才删除临时目录。同步云端关闭接线，不以吞错、固定 sleep 或重试删除掩盖问题。
- [ ] 运行恢复/容量/预算/云端装配目标测试；保留慢任务守卫、幂等重放、故障关闭、容量回滚原有断言。额外记录一次有明确次数的目标回归以检查竞态，不能只挑成功运行汇报。
