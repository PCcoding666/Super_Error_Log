# GitHub 自动发布（2026-10-15）

用户已选择：PR 自动检查；合并到 `codex/ai-error-review-mvp` 后，检查通过自动上线；启动失败自动回退。

## 范围与约定

- 保留现有 CI（Node 24、Vitest、Playwright；涉及 iOS 时跑 Swift）。只有集成分支的 push 可以取得 production 环境密钥；PR 和旧 `main` 不发布。
- 发布前检查远端分支仍指向本次提交。生产发布串行，不取消进行中的发布；被新提交替代的旧运行跳过。
- GitHub 保存专用受限 SSH 密钥。服务器账号仅能提交发布包、查询发布状态；不能取得管理员 shell，不能读取学习数据或 AI 密钥。
- 使用现有白名单打包脚本。服务器校验 SHA256、归档路径/大小/类型及提交清单，生产依赖由独立低权限账号安装（禁用安装脚本）。
- 发布由服务器 systemd 独立执行，关闭电脑、SSH 断开不会中途停止。所有步骤有时限；状态可以重新查询。
- 等当前照片识别/打印处理完，停止服务并再次检查，备份数据、环境和单元文件，原子切换版本，再检查 HTTPS 登录页、静态资源、匿名访问限制和进程状态。等待期间旧版照常服务。
- 启动检查失败恢复旧版本；数据库不自动倒灌，避免覆盖新写入。自动发布仅适用于向后兼容的数据库改动；破坏性迁移须另行安排维护。
- 不更换默认分支、不改业务功能、不删除学生/邀请码，不自动清理历史发布/备份。磁盘不足时拒绝发布。

## 实施顺序

1. 增加可复用部署工作流、受限 SSH 入口及服务器发布程序。
2. 更新 CI/Cloud 交接和发布操作说明，代码审查。
3. 配置服务器专用账号、固定入口、production 环境及专用密钥。
4. 推送 PR；现有检查和发布脚本检查通过后，合并以启用用户批准的自动发布。
5. 记录首个 Actions 发布的提交、备份、健康检查和失败回退验证结果；未验证部分明确标注。

## 完成判定

不仅有 YAML：GitHub 配置就绪，首个合并触发 CI→发布成功，线上版本和该提交一致。测试/审查不使用真实题目或模型；上线冒烟不更改学生记录。
