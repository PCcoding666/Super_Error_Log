# PILOT PROTOCOL — 两周真实学生试用方案

版本：v1.0（2026-09-05）

## 目的

验证 MVP 的核心产品假设是否成立（流程可执行性、维护成本、任务完成率、延迟重做的可行性与负担），**不验证分数提升**。本方案在获得真实数据前，所有效果性结论保持 UNVERIFIED。

## 对象

一名广州执信中学初三住校生，成绩前 20%，工作日不能使用电子设备，每周约 20 道数学/物理/化学错题。家长知情并同意。

## 数据最小化原则

每道题只收集：日期、学科、来源；题目/原始过程/教师批注/标准答案的**去标识化**图片；四项反思；延迟作答结果（是否独立正确、是否用提示、是否完成）；后续同知识点/错因复发。

禁止：收集姓名、学号、班级、学校账号等非必要身份信息；默认把图片用于模型训练；家长查看学生私人反思全文；声称两周可证明分数提升。

## 流程

### Week 0（准备，约 20 分钟）
- 家长知情说明（数据范围、可见边界、可随时退出）。
- 创建匿名学生 ID（不使用真实姓名）。
- 拍教材目录/当前章节或手动选择当前学习范围（用于知识点标签）。
- 记录在校可执行纸质复习的时间窗口（如晚自习前 20 分钟）。
- 确认家庭打印条件（A4、黑白）。

### Week 1
- 周末（目标 ≤ 15 分钟）：上传一周全部错题（约 20 道）。
- 系统识别 + 人工校正低置信度条目。
- 学生完成四项最小反思。
- 系统选择 5–8 道，生成打印复习包。
- 工作日：学生在学校离线完成复习包，勾选结果。

### Week 2
- 周末：回传完成结果（上传完成页或快速录入）。
- 对比主观掌握感与延迟作答结果的差异。
- 系统安排失败/用提示的题进入第二周复习包。
- 再完成一轮。
- 周末结束：30 分钟访谈（学生 + 家长分开进行）。

## 指标（pilot 采集）

| 指标 | 目标/观察点 |
|---|---|
| 周末维护总时间 | 目标 ≤ 15 分钟；记录实际 |
| 每道题学生确认时间 | 目标 ≤ 30 秒 |
| 被安排题目的完成率 | 观察是否可持续 |
| 3–7 天后独立正确率 | 核心行为指标 |
| 提示使用率 | 高提示率说明安排过早或题过难 |
| 主观掌握 vs 实际结果偏差 | 验证「熟悉感≠掌握」在产品中的体现 |
| 同类错误复发 | 趋势页是否帮助学生察觉 |
| 复习包是否被认为是额外负担 | 访谈 |

## 停止或调整条件（任一触发即调整）

- 周末维护持续超过 15 分钟且学生明显抵触。
- 每周任务完成率过低（< 50% 持续）。
- 大量题目必须人工重新录入（识别质量不达标）。
- 打印包与学校作业时间冲突。
- 学生通过背答案而非方法重做（勾选与过程明显不符）。
- 家长监督造成表演性填写。

## 伦理与合规

- 家长书面/口头知情同意（记录方式，不存证件）。
- 学生可随时退出，数据可当场删除。
- 数据仅本地存储，试点结束按约定删除或移交家长。
- 不与学校正式评价挂钩。
