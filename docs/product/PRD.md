# PRD — Super Error Log MVP（纸错题延迟重做闭环）

版本：v1.0（2026-09-05） 状态：与实现保持一致，随实现修订

## 0. 一句话产品命题

> 为工作日不能使用电子设备的高分初三住校生，把一周纸质错题在周末十几分钟内转化成一份可带回学校的个性化复习任务，并通过延迟独立重做而不是抄答案来验证掌握。

## 1. 问题定义与非问题

### 问题
初三住校生的错题几乎全部产生在纸质材料上。现有流程是「老师讲解 → 原卷订正或抄正确答案」，存在四个断点：

1. **行政劳动重**：抄题、写长篇错因、抄错误步骤占用大量时间。
2. **复习无调度**：整理完不知道何时复习；复习时只能重看答案。
3. **掌握无证据**：看懂解析、当场会做被误认为掌握；延迟独立做对才是真正的掌握证据。
4. **学校无屏幕**：工作日不能使用手机/平板，任何依赖 App 的复习设计都不成立。

### 非问题（本产品不解决）
- 不解决「找不到题目做」（不是题库）。
- 不解决「题目不会做时没人讲」（不是搜题/讲题工具）。
- 不解决「课堂知识没学会」（不替代教学）。
- 不承诺两周内提高考试成绩。

### 根因假设
行政劳动挤占了认知劳动；熟悉感被当作掌握证据；缺少跨越「学校无屏幕」边界的任务载体（纸质复习包）。

## 2. 目标用户与 Job to Be Done

### 首要用户（design partner）
- 广州执信中学初三住校生，成绩前 20%，目标是保持高分（CONFIRMED，访谈）。
- 工作日（周一至周五）住校，不允许使用手机/平板；周末在家可使用手机拍照和录入。
- 错题几乎全部来自纸质材料，每周约 20 道；来源大致均布：纸质作业、练习册、周测/月考/模拟、课堂临时题、课外题。
- 通常能拿到标准答案，有老师批注，并保留自己的原始解题过程。
- 首批学科：数学、物理、化学。
- 学生认为「错因分析和反思总结必须由自己完成」。

### 次要用户
- 家长：关心薄弱知识点与任务完成情况，但学生需要保留私人复盘空间。

### 非目标用户
- 工作日可以频繁使用电子设备的学生。
- 需要班级管理的教师（首版无教师端）。
- 小学生/高中生（未验证）。

### Job to Be Done
- 学生：「周末花最少时间把一周的错题变成下周在学校能执行的几道题，并且知道自己是不是真的会了。」
- 家长：「不用盯细节，也能看到孩子最近在哪些知识点上反复出错、任务有没有完成。」

## 3. 流程

### 当前流程（As-Is）
老师讲解 → 学生在原试卷订正或抄正确答案 → 错题留在试卷/练习册里 → 不知何时复习 → 复习时重看答案 → 熟悉感被当作掌握。

### 理想流程（To-Be 愿景）
错题被结构化 → 学生自己确认错因 → 系统按价值与遗忘规律调度 → 延迟独立重做 → 行为证据更新掌握 → 错误模式复发可见。

### MVP 流程（本版本实现的闭环）
1. 周末：学生/家长批量拍摄上传一周的错题图片或 PDF（原题、原始解题过程、教师批注、标准答案）。
2. 系统把非结构化图片/PDF 转成可校正的错题条目（AI 建议学科/章节/知识点/题型/可能错因/复习价值，附置信度；低置信度进入人工校正）。
3. 学生逐题完成四项最小反思：做题状态、主要错因、当前掌握感、复习价值（AI 不得代写提交）。
4. 系统用可解释规则从每周约 20 道中选出 5–8 道高价值题，安排 3–7 天后的延迟重做。
5. 生成可打印的 A4 黑白复习包：题目与答案分离、隐藏答案、足够演算空间、短 ID、结果勾选框。
6. 学生在学校离线完成（无屏幕）。
7. 下个周末：上传完成后的复习包照片或快速录入每题结果。
8. 系统按「是否独立完成、是否使用提示、是否答对」更新题目掌握状态和下次复习时间。
9. 家长只看到知识点薄弱趋势、任务完成和掌握趋势；学生私人反思默认不可见。

## 4. 产品原则与反模式

原则：
1. 学生中心不等于照单全收功能愿望；行为证据优先于口头偏好。
2. AI 负责结构化、建议、排序、调度、提示和汇总；学生负责确认错因、独立重做和必要反思。
3. 优先消除行政劳动，不消除必要认知努力。
4. 「看懂」「当场会做」「延迟独立做对」是三种不同状态。
5. 不以错题收录量、AI 对话次数、打开次数作为北极星指标。
6. 不让错题无限堆积；必须支持「不值得长期保留」。
7. 工作日必须完全可离线、无屏幕完成。
8. 默认收集最少数据；未成年人数据去标识化，不默认用于训练。
9. 所有 AI 结论显示置信度或不确定性；低置信度进入人工校正。
10. 先最小完整闭环，再增加知识图谱、变式题、复杂家长端。

反模式（明确反对）：
- AI 一键生成错因反思并自动保存（替代学习）。
- 把全部错题无差别纳入长期复习（堆积）。
- 工作日推送通知、打卡、屏幕交互（违反学校场景）。
- 家长端展示学生私人反思全文（监控过度）。
- 用「掌握率百分比」等无法解释的指标包装规则系统。

## 5. MVP 范围与非目标

### 必须做（本版本）
- 中文响应式 Web，周末手机优先，桌面可用。
- 单个匿名学生档案；学生视图 + 家长聚合视图。
- 数学、物理、化学录入。
- 图片/PDF 批量上传；上传批次与处理状态。
- 错题切分/提取的 AI provider 接口 + deterministic mock + 低置信度人工校正。
- 错题条目可查看原题图、原始解题图、教师批注/答案图。
- 学生四项最小反思（做题状态/主要错因/掌握感/复习价值）。
- 可解释的复习价值评分及理由。
- 每周 5–8 题复习计划。
- A4 黑白打印友好 PDF 复习包：题目与答案分离、演算空间、短 ID。
- 复习结果快速录入；可上传完成页并与题目匹配；识别失败可手动确认。
- 状态流转与下次复习调度。
- 薄弱知识点与错误模式趋势。
- 学生私人反思与家长视图隔离。
- 可重复 demo seed 数据。
- 无 API Key 时 mock 完整可用；配置 OpenAI-compatible 服务后可切换真实识别。

### 暂不做（明确非目标）
- 全教材知识图谱。
- 与学校 LMS、微信、教务系统集成。
- 大规模公开题库。
- 全自动高可靠手写数学判分；主观题全自动评分。
- 复杂班级/教师后台。
- 游戏化、排行榜、社交。
- 付费、订阅、生产级多租户。
- 声称两周内提高考试成绩。

## 6. 功能需求（用户价值 / 行为要求 / 验收标准）

### F1 匿名学生档案与首次设置
- 价值：无需账号体系即可使用，保护未成年人隐私。
- 行为：创建匿名档案（昵称可虚构）；选择学科（数/理/化）与周末处理节奏；看到隐私边界说明。
- 验收：J1 E2E 通过；无任何真实身份信息必填项。

### F2 周末批量上传
- 价值：10–15 分钟处理一周错题。
- 行为：一次上传多张图片或一个多页 PDF；显示批次处理进度；单个文件失败不破坏整批。
- 验收：J2 E2E；重复上传同一文件幂等（不重复创建条目）；超大/不支持格式/空文件有明确反馈。

### F3 错题提取与低置信度校正
- 价值：消除抄题劳动。
- 行为：AI（或 mock）将图片/PDF 切分为错题条目，建议学科/章节/知识点/题型并给出置信度；低置信度条目醒目标记，用户可修正题目范围与字段。
- 验收：20 道合成 fixture 全流程；低置信度项可校正保存；AI 失败可重试或转人工录入。

### F4 学生四项最小反思
- 价值：保留必要认知努力，形成错因数据。
- 行为：学生逐题确认四件事（见状态机附录）；AI 可建议但不得自动提交；反思保存前必须学生主动确认。
- 验收：J3 E2E；不存在「AI 代提交」路径；反思内容不进家长端。

### F5 复习价值评分与本周计划
- 价值：从 20 道题中选出最值得延迟重做的 5–8 道。
- 行为：系统给出每题评分与可解释理由；学生可覆盖选择；计划固定为 5–8 题。
- 验收：评分规则单元测试；理由文案对每题可见；J4 E2E。

### F6 A4 打印复习包
- 价值：工作日无屏幕执行载体。
- 行为：生成黑白 A4 PDF；题目页无答案与原错误答案；每题有演算空间、短 ID、计划日期、结果勾选框；提示与完整答案分离（答案在末页，可裁开）。
- 验收：PDF 程序检查（无答案文本泄露、页尺寸 A4）+ 视觉检查（无裁切、公式可读）；包内条目可追踪到错题 ID。

### F7 结果回传
- 价值：闭环的输入端。
- 行为：上传完成页照片自动按短 ID 匹配题目，或手动快速录入：独立完成/做出但不确定/使用提示/完全不会/未完成 + 是否正确。
- 验收：J5 E2E；四种结果各产生正确状态；匹配失败可手动确认。

### F8 掌握状态与调度
- 价值：用行为证据替代熟悉感。
- 行为：按状态机规则更新；失败与用提示的题优先进入下次计划；暂时掌握 7–14 天后安排确认。
- 验收：状态机单元测试 + J6 E2E；规则可解释并在 UI 可见。

### F9 趋势与家长视图
- 价值：家长了解薄弱点而不侵入私人空间。
- 行为：学生端看详细；家长端只看聚合：薄弱知识点趋势、任务完成率、掌握趋势；不显示任何反思文本与原图细节。
- 验收：J8 权限 E2E（含直接 URL/API 访问被拒测试）。

### F10 AI 降级与 mock
- 价值：无 Key 也能完整演示与测试。
- 行为：未配置 Key 时自动使用 deterministic mock；provider 超时/非法 JSON 时可重试或转人工。
- 验收：J7 E2E；同一 fixture 的 mock 输出稳定可复现。

## 7. 非功能需求

- 隐私：数据最小化；匿名 ID；本地存储；反思文本不进日志；图片内容不进日志。
- 性能：周末 20 道错题批次在 mock 模式下处理 < 30 秒；页面在手机上可单手操作。
- 可恢复：批次处理可重试且不产生重复错题（幂等键）；失败有明确状态与重试入口。
- 可访问性：键盘可操作；表单有标签与错误提示；loading/empty/error/partial/low-confidence 状态明确。
- 可维护：TypeScript 全栈；业务逻辑与 AI provider 解耦；一条命令启动、一条命令完整质量检查。

## 8. 权限与隐私边界

|---|---|---|
| 错题条目/图片 | ✅ | ❌（仅聚合统计） |
| 四项反思内容 | ✅ | ❌ |

| 薄弱知识点/错误模式趋势 | ✅ | ✅（聚合） |

- 日志不得包含反思全文、图片内容、secret。
- fixture 全部为匿名合成数据。

## 9. 状态机

### 9.1 错题状态机（ErrorItem.status）
```
captured               已从批次中提取（未校正）
needs_review           低置信度或异常，等待人工校正
ready_for_reflection   校正完成，等待学生四项反思
eligible_for_review    反思完成，可被复习计划选中
scheduled              已进入某周复习计划
packet_generated       已随复习包打印下发
attempted              已回传作答结果
needs_recheck          作答失败/用提示/不确定，需再次安排
temporarily_mastered   延迟 3–7 天独立做对（暂时掌握）
stably_mastered        暂时掌握后 7–14 天再次独立做对（稳定掌握）
archived_not_worth_review  不值得长期保留（学生判断+系统无复发证据）
```
流转规则：
- captured →（置信度低/数据不全）→ needs_review →（人工校正）→ ready_for_reflection
- captured →（置信度正常）→ ready_for_reflection
- ready_for_reflection →（学生提交四项反思）→ eligible_for_review
- eligible_for_review →（被选入计划）→ scheduled →（生成 PDF）→ packet_generated →（回传结果）→ attempted
- attempted →（独立做对且在延迟窗口）→ temporarily_mastered
- attempted →（使用提示/做错/不确定/未完成）→ needs_recheck →（再次被选入计划）→ scheduled
- temporarily_mastered →（7–14 天确认独立做对）→ stably_mastered；→（确认失败）→ needs_recheck
- eligible_for_review/attempted →（学生标记「没必要再做」且系统无复发证据）→ archived_not_worth_review

### 9.2 掌握规则（可解释，写入 UI）
1. 刚看过解析或当场重做正确，**不算**延迟掌握（不产生掌握事件）。
2. 3–7 天后不看答案独立做对 → temporarily_mastered。
3. 使用提示、部分完成或做错 → needs_recheck，并优先出现在后续复习包。
4. temporarily_mastered 在 7–14 天后安排一次确认；再次独立做对 → stably_mastered。
5. 一道题掌握不代表错误模式消失；同一错因或知识点重复发生时，趋势页单独提示复发。

### 9.3 复习价值评分（第一版为可解释规则，不伪装成已验证的个性化算法）
基础分 0–100，加分项：
- 错因为知识概念/方法选择/推理步骤 +30；计算/审题/表达/状态类 +10（一次性低价值笔误不加分）。
- 同知识点或同错因在本周/历史复发：每次 +15（上限 +30）。
- 学生标记「必须再做」+15；「可以再做」+5。
- 冲突信号：学生认为「没必要」但系统证据显示复发 +20 并显示冲突提示。
- 题目标记为关键方法或前置知识缺口 +10。
- 已安排但未完成的积压 +20。
- 学生当前掌握感 0–1 分 +10。
选择规则：按分排序取 Top 5–8；若 eligible 不足 5 道则全部纳入并提示；同知识点最多 2 道（避免一包同构）。

## 10. 学生最小输入契约（附录 B 固化）

每题反思四项：
1. 做题状态：完全不会 / 知道考什么但没想到方法 / 方法基本正确但步骤出错 / 本来会但审题计算书写失误 / 时间不足 / 其他
2. 主要错因：知识概念 / 方法选择 / 推理步骤 / 计算 / 审题遗漏 / 表达规范 / 时间注意力状态
3. 当前掌握感：0 仍不会 / 1 看提示可能会 / 2 现在重做应该会 / 3 隔几天也有把握
4. 复习价值：必须再做 / 可以再做 / 没必要再做

回传只记录：独立完成 / 做出但不确定 / 使用提示 / 完全不会 / 未完成；是否正确；卡住的步骤（可选）。

## 11. 指标体系

### 北极星指标
- 每周被安排错题的延迟独立正确率（3–7 天后不看答案做对的比例）。

### 过程指标
- 周末批量处理总时间（目标 ≤ 15 分钟）。
- 每道题学生确认时间。
- 被安排题目的完成率。
- 提示使用率；失败后再次安排率。
- 学生主观掌握感与实际结果偏差。

### 防作弊/健康指标
- 同知识点/错因复发趋势（单题掌握不能掩盖）。
- 复习包是否被认为是额外负担（pilot 访谈）。
- 不以收录量、AI 对话次数、打开次数为成功指标。

## 12. 风险与验证假设

最高风险假设（详见 ASSUMPTION_REGISTER）：
1. 学生愿意连续两周执行该流程（UNKNOWN）。
2. 周末维护 10–15 分钟目标真实成立（UNKNOWN）。
3. AI/mock 对真实纸质材料的切分与字段建议足够准确（UNKNOWN，mock 仅演示流程）。
4. 5–8 道/周的数量合适（UNKNOWN）。
5. 延迟复习能减少真实考试中的重复错误（UNKNOWN，自动化无法证明）。

## 15. 伪需求反证记录

| 伪需求 | 反证结论 |
|---|---|
