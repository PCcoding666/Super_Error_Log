# 错题分类 PR1：基础结构与初中目录

## 交付范围

基于 `main` 的 `d3ac4a9`，新增按学段、学科、知识点组织的分类基础。当前默认初中，三科目录包含数学 32、物理 30、化学 25 个知识点（共 87 个），附初始同义名称。目录不绑定教材版本，不宣称覆盖全部教学大纲。

每个学生的目录独立；学科标准键与展示名称分离。目录首次读取时事务化初始化，之后不重新灌入种子数据，因此不会覆盖改名或复活已删除/合并的条目。错题可关联多个同科知识点；数据库约束学生、学段和学科归属。照片任务也预留手动选科关联，用于识别尚未建题的阶段。学科与知识点分别保留 AI/人工来源及人工确认状态，历史批次/任务表为后续 PR 预备。

此 PR 不新增页面入口、不运行 AI、不整理历史题、不修改现有 `subject/knowledge_tags` 或学习状态。学科管理、自动归类和筛选由后续 PR 接入。

## 验证记录

- 先运行新增迁移测试，15 项因缺少分类表失败；实现后全部通过。
- 目录服务新增 8 项测试，迁移与目录合计 23 项通过。
- 独立审查发现 SQLite 普通 rowid 表的 `TEXT PRIMARY KEY` 可为空，从而绕过复合外键并留下孤立分类记录。复现后增加 5 项测试（分别覆盖 5 张表的省略 ID、显式 NULL），先失败，再对新增单列主键补显式 `NOT NULL`，28 项专项全部通过。未改动旧表主键约束。
- 拍照时手动选科的持久化关联，两项回归先失败再通过；专项合计 30 项，覆盖建题前保存、重复启动、跨学生/学段拒绝、空照片编号拒绝及照片删除后的清理。补充关联经过独立审查，未发现重大问题。
- 最后完整运行 `SEL_AI_MODE=mock npm run verify`，退出码 0：类型检查、构建通过，Vitest **835 通过/5 条条件跳过**，Playwright **37 通过/6 条条件跳过**。其中新增分类专项共 30 项。
- 运行 `python3 -m unittest discover -s tests/deploy -p 'test_*.py'`，确认现有部署测试通过；没有修改发布程序和工作流。
- 全部使用合成数据及 mock provider；不读取真实照片、会话或生产数据库。条件跳过包括 Linux 不支持的 macOS HEIC、未配置 Caddy 的测试，以及需显式开启的质量证据采集。

## 发布状态与人工验收

当前尚未发布；当前生产版本不能以本文件或本地检查推断。用户已授权各 PR 合并发版，但第一个 PR 涉及 `dist/db` 变化，现有发布程序会以 `Database migration code changed; manual release required` 拒绝自动发布。

依据：`deploy/ci/README.md` 的失败与恢复部分明确要求人工发布和迁移验收，并禁止迁移绕过保护。保留该限制；管理员入口由用户安排。在人工发布可执行前，不以必然失败的自动部署替代交付，也不报告为已上线。

具备管理员入口后的检查顺序：

1. 确认 PR 的 CI、审查、发布包 SHA256 与将部署的提交一致，按已有发布流程检查旧服务健康及识别/打印空闲。
2. 停服务后做一致性备份，包含当前数据库/WAL、学生空间、照片和配置，保留旧版本指向。不要将备份上传仓库。
3. 先在旧数据库副本执行新增建表 SQL；核对旧错题/证据/复习/回传记录数量、分类外键检查及重复执行结果。只核对聚合，不输出学生内容。
4. 通过既有受控人工流程部署。旧入口、设置、拍照、错题查看应保持可用；本 PR 不应触发 AI 历史整理。
5. 记录实际线上提交、版本、HTTPS 检查和学生空间迁移结果，再向用户汇报。代码回退不直接恢复旧数据库，避免覆盖发布后的新记录；新增表可保留以兼容旧代码。

后续 PR 只有在本 PR 发布完成并汇报后，才进入下一次合并发版。
