# 手机相册批量上传验收

日期：2026-10-15。此记录对应基于最新 `origin/main` 的 `codex/mobile-album-batch-upload` 分支；本次改动尚未合并或部署。

## 行为

- 相册一次选择多张后自动上传，无需逐张确认；直接拍照仍使用独立的单张相机入口。
- 每张显示文件名、等待/准备/上传/成功/失败状态及进度；整批显示成功张数、百分比与失败张数。百分比按照片等权计算，失败项不计成功，最后一张等待服务端确认时整批最多显示 99%。
- 图片准备与上传共用单并发队列，匹配服务端唯一上传槽位。沿用最长边 4096 的 JPEG 转换、质量阶梯、元数据清理、30 秒准备超时和 120 秒上传超时，以及现有服务端识别、登记与去重流程。
- 单张失败后继续处理其余照片。部分失败不刷新页面，成功照片的数量、缩略图与结果保留；可以查看已上传照片，或只重试可恢复的失败项。另选照片会追加到队列，不会重传之前的成功项。
- 每张独立保留同一个幂等标识和转换后的 JPEG；重试复用原字节。上传期间锁定选择与重试入口，重复选择事件、表单提交和连续重试点击均不额外提交。
- 成功项释放原文件和转换结果的引用；原有画布与 object URL 清理保持不变。全部成功后刷新到服务端照片列表。
- 手机上重试入口位于逐张列表之前；已有成功照片后收起拍摄提示，底部相机入口改为“再拍一页”。保留主线的 CSS/JS 内容指纹缓存更新机制，进度条继续使用 transform 动画。
- 适配主线的局部增强与后台轮询：未完成或失败批次保留在当前页时暂停局部替换，早于上传发起的轮询响应也不覆盖成功结果与重试入口。
- 无脚本时保留原有单张表单；只在脚本启用时打开相册多选，避免多选原图表单仅处理第一张。

## 自动化验收

测试均使用隔离的临时学生空间、合成图片与 mock 识别，不使用真实学生照片或真实模型。

`tests/e2e/photoUpload.spec.ts` 新增覆盖：

| 场景 | 断言 |
| --- | --- |
| 一次选择 5 张，第 3 张网络失败 | 首轮恰好 5 次上传、4 个不同识别任务；4 张完成找题并出现在服务端照片页；页面保留 4 个成功和 1 个失败结果，整批进度为 80% |
| 只重试失败项并连续点击 | 总请求数从 5 增至 6；第 6 次的标识、JPEG 哈希和尺寸等与第 3 次相同；最终 5 张照片，无成功项重传；全过程最多 1 个上传 |
| 逐张及整批进度 | 前 4 张成功、第 5 张上传 50% 时，逐张显示 50%、整批显示 90%；第 5 张发送完成而未确认时整批为 99%；服务端确认后显示 5 张并刷新 |
| 服务端成功、响应丢失 | 重试仍返回相同任务 ID；两次请求的标识与转换后字节完全相同，照片只有 1 张 |
| 中间照片无法解码 | 后续照片继续上传；文件名作为文本展示；不提供无效的原图重试；重选追加时先前成功结果保留 |
| 后台局部更新 | 已发起的轮询及后续轮询响应在批次开始后返回，均保留本地上传结果；轮询在上传前已更新区域时，后续上传使用当前缩略图区域和拍照入口 |
| 手机操作位置 | 部分失败时重试按钮位于首屏底栏以上，拍照入口保留且文案为“再拍一页” |
