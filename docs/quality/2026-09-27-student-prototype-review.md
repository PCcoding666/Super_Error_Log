## R4 验收结果（Codex 独立浏览器实测，2026-09-27，WorkBuddy 嵌入预览；非真机/非原生验收）

Codex 在新的 WorkBuddy 嵌入预览中独立测试 r4，人工放行链路全部按预期：

1. 看原图之前，放行按钮保持禁用。
2. 看过原图后点击放行，页内确认对话框正常打开；默认焦点在「暂不放行」。
3. Tab 在「暂不放行」与「确认放行」之间循环，焦点不出对话框。
4. Escape 取消：题目保持 needs_check 不变，焦点回到放行触发按钮。
5. 显式「确认放行」：只放行当前题，并直接进入第 2 题的复盘。
6. 进入复盘时选项为空、「保存复盘」在学生作答前保持禁用。

以上仅为浏览器原型验证，不构成真机、原生 SwiftUI、VoiceOver 或 Liquid Glass 验收；其余未验证项（真实识别质量、真机体验等）维持前文声明，不扩大结论。

## R2 验收结果（Codex 独立浏览器实测，2026-09-27；非真机/非原生验收）

Codex 在浏览器中独立试用 r2，主流程与核心返修通过：

1. 未看原图不可确认 → 看原图勾选后可确认；普通确认提示「已确认」并直达同题复盘。
2. 手动填 4 项 + 备注保存后重新进入，内容原样保留。
3. 离线情境下即使看过原图并勾选，确认按钮仍禁用；已确认题可离线进入复盘。
4. 重试第 2 题只把该题 failed→ready，第 1 题 confirmed 与第 3 题 ready 保留。
5. 大字号真实生效：根字号 16→19px，题干 15.2→18.05px；320px 宽 + 深色 + 大字号下内容区 scrollWidth == clientWidth（318），无横向溢出。
6. 零候选、全跳过、503 只给重试连接、401 才引导重新配对、处理中「1 待核对 + 2 识别中」文案均如预期。

## 五个返修点的逐项回应

### 1. 杀 App ≠ 云端 interrupted
- 核实证据：`StudyStore.swift` 286–327 行——`pausePolling()` 只取消客户端轮询 Task；`refreshJobs` 是只读拉取，云端任务状态完全由服务器推进。
- 文档修订：状态表新增「重新打开 App」行（先显缓存 + 最后更新时间 → 刷新云端真实状态，不触发重跑）；「中断恢复」行明确 interrupted 仅由服务器判定；验收第 4 条整段重写为「重新打开，不变更云状态」（以服务器 `jobs/<id>/job.json` 状态/revision 零变化为判据）。
- 原型对应：情境⑧「重新打开」——先显缓存条（上次更新于 11:18），云端状态只能由控制台「模拟云端返回最新状态」这一显式动作更新，无定时器、无自动进度。

### 2. lastError ≠ 离线
- 核实证据：`StudyStore.swift` 321–327 行——任何刷新错误（超时/5xx/解码失败）都写进同一个 `lastError` 字符串。
- 文档修订：M1 第 5 项强化 + 状态表拆出六行：设备离线 / 进度暂未更新（不确定）/ 服务暂不可用 / 配对失效 / 媒体读取失败（仅该题受影响）/ 原离线恢复行。明确「禁止把所有卡片标记为任务失败」。
- 原型对应：情境⑥（离线：灰条 + 缓存可看 + 重试入口）与情境⑦（连接失败/配对失效 + 卡片「进度暂未更新 · 上次更新于 …」+ 重试/重新配对按钮）分开呈现。

### 3. 取消 skipped「一键恢复」承诺
- 核实证据：`src/mobile/service.ts` 223–250 行 confirm 仅支持 `confirm`/`skip`（且已确认不可跳过），158–190 行 retry 仅接受 `failed` 题；`RecognitionClient.swift` 123–130 行一致。恢复已跳过题**无接口**。
- 文档修订：题目级词表改为「已跳过 · 只可查看」，恢复列为未来接口需求；M1「稍后核对」仅退出页面、不调用持久 skip；既有持久「暂不处理」保留但确认弹窗须如实说明不可恢复。
- 原型对应：情境⑤全部跳过——卡片区显示「仅可查看 · 当前版本不能恢复」，题目详情无任何恢复按钮；题目详情的「稍后核对」按钮只做返回、不改状态。

### 4. 状态聚合精确定义
- 核实证据：`ThisWeekView.swift` 155–157 行确实以「无 ready/needs_check ⇒ 已全部确认」推断，零候选/全跳过/全失败都会被误报为「已全部确认」。
- 文档修订：新增 5.0 节聚合规则表（零候选、全部 skipped、confirmed+failed、ready+processing 混合、未知 status 全覆盖；仅题目数>0 且全 confirmed 才叫「全部已确认」；「已处理」含失败、needs_check 不叫「可用」；处理中不阻塞核对）。
- 原型对应：`photoSummary()` 单一函数实现同一套规则；情境②（识别中可先做已就绪题）、③（混合失败）、④（零候选显示「没有发现可识别的题目」）、⑤（全跳过）可直接点击验证。

### 5. 其他叙述更正
- 「全仓无 AVFoundation」更正：`SourcePhotoView.swift`、`CameraScanner.swift` 均已 import AVFoundation；准确表述为无 Speech/SFSpeechRecognizer/麦克风使用。
- 方案三否决理由更正：用户反对的是开屏教程/欢迎页，不是清楚的分步任务流程；否决原因是强制单一路径掩盖异步状态。
- M2 补充：ASR 端上中文识别质量/机型可用性未实测、不承诺；键盘路径永远保留；M2/M3 保持未来边界，原型中不放语音/归类假按钮（题目详情有明示文字说明属下一阶段）。

## 原型说明

- 主推路径完整可点：本周 → 照片卡（整卡可点）→ 题目详情 → 打开完整示例原图（可缩放查看器）→ 勾选「我已对照原图」→ 确认（此前按钮禁用）→ 直接进入该题复盘 → 学生自己点选+填写 → 保存。
- 复盘门禁：仅 confirmed 题可进复盘；未确认/失败/已跳过题无入口，复盘 Tab 也不列出。
- 重试为显式演示动作，只把目标失败题改为待确认，其他已确认项保留（情境③可验证）。
- 深浅色、大字号、窄屏开关在控制台；按钮均 ≥44px、语义 `<button>`、可键盘操作（Tab/Enter/空格）；原图为 HTML 排版的示例纸面题目，多处标注「示例 · 演示数据」。
- 每页顶部固定横幅「交互原型 · 演示数据，不是真实识别」。
