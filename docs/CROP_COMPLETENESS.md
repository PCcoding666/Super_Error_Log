# 裁图完整性检查

范围：现有 TypeScript 证据提取、校对、确认、反思、选题和打印链路。不是 OCR 字符置信度，不是“框在图内”，不是数学解答正确率，也不是学生错因判断。

## 判定标准

- 题目：完整条件、所有选项、共享题干、每一小问和必要图示。少一个负号、换行数字、下标也可以是不完整。
- 图示：必要线/轴、箭头、点、标注和关系完整。不为干净打印增加解出的坐标或答案。
- 学生原始作答、订正和其他证据：各自可见的全部表达式和步骤，包括分子、分母、符号。不能凭颜色猜作者。
- 完整性与纯净度分开。审阅用题目裁图可以完整但带邻题；打印只排版校对后的题干和经过纯净度检查及人工确认的图示，不打印整张题目审阅裁图。
- 边缘接触是警告；确认截断是缺失；看不清是“不确定”，不能用模型总体置信度覆盖。

## 自动流程

真实 `StagedProvider.extractItems` 每题转写后自动调用 `CropAuditor`。已有题或改框后的题，在证据页点击“对已保存版本运行自动裁图检查”。GET 浏览、预览、改框和保存草稿均不调用模型。

每个目标有两个独立请求：

1. `crop_inventory` 只看原图，按指定题号独立建立必需元素清单。不提供候选转写或裁框边界；证据小区域只提供定位锚点，不能据此断言作者。返回实际识别题号，程序拒绝题号不匹配。
2. `crop_verify` 同时看原图、扩大上下文和实际裁图，逐项检查清单。只有在实际裁图可见才是 `present`；核对候选转写与原文是否一致。发现清单之外的遗漏仍记录。

程序拒绝空清单、重复 ID、漏检 ID、不合法字段。完整性根据逐项结果推导，不信任模型自报的总体 `pass`。原图不清或有任何未解决不确定项不能得到完整性通过。

一轮最多 12 个目标（包括整题框）、24 次请求，串行、无自动重试。超限目标记为未检查并阻止确认；再次点击在相同源图、证据和策略下只续查未检查区域，不重跑首批。全部目标已检查后主动重跑会开始新一轮。扩大按钮只扩大原框四周并限制在原图边界内，保存草稿、使旧检查失效；不会自动用扩框结果替换已确认题面或抹去答案。

图示检查额外返回 `coveredDiagramIds`，把实际裁图与整题清单中的必要图示逐项关联。所有必需图示元素必须被完整、纯净的打印图示裁图覆盖，不能只因“存在一张图”就通过多图题。

模型输入保留整页和实际裁图；重复大图导致保守输入预算超限时，优先缩小原图/上下文总览，必要时限制模型裁图长边。记录实际裁图及发送给模型的图片摘要，源文件不改写。缩放可能影响细字辨认，仍允许不确定，不能把模型图像的可读性当成原图质量。

## 状态不是同一回事

| 字段 | 可能值 | 含义 |
|---|---|---|
| `technicalStatus` | `completed / failed / not_checked` | 请求和清单结构是否完成，不是内容验收 |
| `completeness` | `pass / missing / uncertain` | 必需内容是否保留；pass 仍只是模型建议 |
| `purity` | `clean / contaminated / uncertain` | 是否含邻题、答案、批注等额外内容 |
| `textFidelity` | `match / mismatch / uncertain / not_applicable` | 转写是否忠于原图，不代表数学答案正确 |

旧评测 `status=succeeded` 保留为历史调用/结构状态，不改写原始评测结果或评分卡。接触表已明确标为 `API/schema: succeeded | CONTENT: NOT CHECKED`。人工审核和自动审核不能伪装成彼此。

## 业务与一致性门禁

报告绑定源文件 SHA-256、规范化后的证据指纹和检查策略版本。指纹包括题号、题干、框、证据文本/归属等；仅人工 `cleanForPrint` 勾选不改变源证据指纹。检查保留请求摘要、响应摘要、裁图摘要、模型、提示词版本和 usage。结构校验失败也保留已经返回的 usage、响应摘要及 `failurePhase`，包括源清单题号不匹配；未返回的调用费用未知，不能记为零。不把提供方原始错误或凭据写入业务记录。

- 上传后的模型通过不会自动确认；仍需用户核对原图、图示和归属。
- 未检查、缺失、不确定、文本不一致、未定位的观察证据不能自动放行。必要图示必须纯净并由人工确认；学生作答、订正等角色区域也不能相互混入。
- 原图、证据或策略改变后必须重新检查。确认、反思、选题、诊断、打印预览及已生成 PDF 的下载均检查当前证据；不能靠旧 `verified` 或历史 PDF 绕过。过期下载/预览返回 409，保留历史文件不删除。
- 保存草稿使旧 AI 诊断/提示失效，证据变化也使裁图报告失效。检查期间的旧版本返回不能覆盖新版本。同一进程内重复检查请求被拒绝。
- 复习包中的证据仍保持锁定。旧数据新增可空 `crop_audit_json` 列，不删除旧记录、不补造审核通过。旧已锁定题需要重新提取为新候选再检查，不原地改动已经发出的纸面记录。

## 配置

新增可选环境变量（空值沿用 `SEL_AI_MODEL`）：

```dotenv
SEL_AI_MODEL_CROP_INVENTORY=
SEL_AI_MODEL_CROP_VERIFY=
```

沿用本机北京百炼接口和密钥；无真实配置不会降级为 Mock。模型效果需实测，不自动修改默认模型。单一 Q9 样本不能证明通用准确率。

## 模型误报的人工处理

已经执行检查的区域，可展开“人工逐项复核并记录依据”。用户必须手填必需内容清单及至少8字依据，明确勾选已对照原图、实际裁图完整、转写正确（有转写时）、证据纯净（非题干区域）。图示还要明确选择实际覆盖的必要图示元素。

人工记录单独保存为 `humanResolutions`，绑定源图、证据、策略及对应模型检查的摘要，保留模型原始缺失/不确定/失败判定。完成单区域复核不会自动将题目标记为已确认，仍需最后确认。未执行的区域不能靠这个入口跳过；旧图/旧框/旧模型结果的人工复核不能复用。未解决的其他区域或缺少图示覆盖仍然阻止放行。

这是用户主动承担的视觉校对，不是模型准确率提高，也不是助手代填的学生反思。真实试验没有替用户填写该记录。

保守边界：整题原图清单本身尚未有效建立时，不能人工通过整题，必须重新检查。自由文本复核清单不替代结构化的必需图示清单，避免多图题仅打印其中一图。其他区域失败后的人工复核仍受整题图示覆盖门禁约束。

## 限制

检查器自身也是视觉语言模型，可能清单漏项、错读、把原图内容混同裁图内容或给出错误判断。题号校验、逐项契约和状态门禁只能减少部分风险，不是完整性的形式化证明。现阶段必须人工复核，不根据两个模型一致就自动放行。模型误报可以按上述有记录的人工流程处理；没有无依据的“一键忽略全部警告”。

真实检查记录保存在忽略的 `data/real-pilot-20260907/crop-audit-v1/`。合成 HTTP/数据库/图像测试验证的是程序行为，不是模型识图质量；真实回测结论另列。
